## Task 6: 章节内容创作流程（循环执行至 4 章完成）

对每个章节（chapterIndex = 0..3）执行以下步骤：

- [x] Task 6.1: 章节内容生成
  - 调用 `generateChapter(projectId, chapterIndex)`
  - 为当前章节提供 AI 生成按钮功能（通过 IPC 调用）
  - 记录生成时间、分片数、模型配置

- [x] Task 6.2: 剧情审核与修正
  - 对生成内容执行剧情检查（调用 V2 剧情检查 API）
  - 针对检查结果中的每条建议，提供独立的单条修正按钮（**已新增功能**）
  - 根据剧情检查建议，对文本内容进行针对性修复
  - 记录修正前后的内容对比及修改记录
  - 实测：第 1-3 章检查评分 88/65/72，单条修正各 2 条全部成功，diff 记录完整
- [x] Task 6.3: 表格整理与应用
  - 完成剧情检查后，进入表格整理功能
  - 将当前已完成的章节内容整理为标准表格格式（调用 TableOrganizeService）
  - 验证表格数据的完整性和准确性（字段齐全、行数正确、内容匹配）
  - 记录表格整理耗时、sheet 数量、行数
  - 实测：第 1-3 章表格整理 5 sheet / 16/25/32 行，验证三项全 true；已修复无 API Key 本地引擎下抛错 Bug
- [x] Task 6.4: 上下文提示注入
  - 生成下一章节前，将已整理的表格内容作为上下文提示词注入生成管线
  - 确保 AI 能够获取并利用之前章节的剧情信息进行连贯创作
  - 记录注入的表格数据摘要（字数、sheet 数、行数）

- [x] Task 6.5: 循环执行
