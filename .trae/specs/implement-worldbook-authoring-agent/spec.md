# 世界书编写智能体（WorldBook Authoring Agent）Spec

## Why

当前世界书完全依赖手动编写，用户需逐条创建条目、设计关键词、编写内容、维护逻辑一致性，工作量大且容易遗漏设定维度。项目已完成 AI 智能体技术底座（`src/main/services/agent/`）并落地了写作智能体（`WritingAgentService`）与世界书工具组（`worldbookTools.ts`），但缺少一个面向世界书构建的高层编排智能体——能够通过"用户初始提示 → 智能体自驱扩展 → 编写过程审计"的闭环，实现世界书的自动化编写，同时保持与手动编写一致的质量标准。

本 spec 设计第一个世界书编写智能体，复用现有底座能力（agentCore / worldbookTools / MemoryStore / steerEngine / goalTracker / autoGenerated 草稿区），借鉴 openclaw 的任务驱动行为模型、多轮对话上下文管理与自主决策机制，构建启发式对话 + 自驱编写 + 审计闭环的三阶段工作流。

## 设计理念（借鉴 openclaw）

### 1. 任务驱动行为模型（Task-Driven Behavior）
借鉴 `openclaw-main/src/agents/config.ts` 的任务驱动策略：智能体始终围绕一个显式 `AuthoringGoal`（编写目标）行动，而非自由对话。目标包含：世界书主题、目标维度清单、目标条目数、质量门槛。

### 2. 多轮对话上下文管理（Multi-turn Context Management）
借鉴 `openclaw-main/src/agents/context.ts` 的会话快照与状态持久化：`AuthoringSession` 持久化到 MemoryStore，进程重启后可恢复。对话状态机：`PLANNING → AUTHORING → AUDITING → AWAITING_REVIEW → COMPLETE`，每个状态有明确的进入/退出条件。

### 3. 自主决策与任务切换（Autonomous Decision）
借鉴 openclaw 的决策点机制：智能体在 PLANNING 阶段自主决定"何时提问澄清"vs"何时直接生成计划"；在 AUTHORING 阶段自主决定"按计划顺序生成"vs"根据上下文跳转维度"；在 AUDITING 阶段自主决定"自动修复"vs"提示用户"。

### 4. steer 行为引导（借鉴 openclaw steer + 现有 steerEngine）
复用现有 `src/main/services/agent/learning/steerEngine.ts`：在智能体偏离质量标准时注入 steer 消息（如"条目内容过短，请扩展""关键词与内容不匹配"），引导其回到正轨。

### 5. goal 目标追踪（借鉴 openclaw goal + 现有 goalTracker）
复用现有 `src/main/services/agent/learning/goalTracker.ts`：追踪编写目标完成度（已生成维度数 / 目标维度数、已生成条目数 / 目标条目数、审计通过率），阻塞计数器超阈值时标记 blocked。

### 6. 防失控调度（pacing/stagger）
复用现有 `src/main/services/agent/learning/pacing.ts` + `stagger.ts`：自驱编写循环的每轮间隔钳位（min 2s / max 30s），避免密集 LLM 调用成本失控；审计反思阶段 5 分钟冷却（复用 feedbackLoop 冷却机制）。

## ADDED Requirements

### Requirement: 三阶段启发式工作流
系统 SHALL 提供一个三阶段世界书编写工作流：**规划（Planning）→ 自驱编写（Authoring）→ 审计闭环（Audit）**，每个阶段有明确的输入、输出与状态转移条件。

#### Scenario: 用户初始提示触发规划阶段
- **WHEN** 用户在 `WorldBookAuthoringModal` 中输入初始提示（如"为一部赛博朋克侦探小说创建世界书"）并点击"开始"
- **THEN** 智能体进入 `PLANNING` 状态，分析提示，识别设定维度（世界观/核心势力/关键人物/地点/科技/规则），主动提出 2-4 个澄清问题（如"故事发生在哪个年代？""主角属于哪个势力？"）
- **AND** 用户回答后，智能体生成结构化 `AuthoringPlan`（维度清单 + 每维度目标条目数 + 关键词策略 + 质量门槛），进入 `AUTHORING` 状态

#### Scenario: 自驱编写阶段无需用户介入
- **WHEN** 智能体处于 `AUTHORING` 状态
- **THEN** 按 `AuthoringPlan` 逐维度调用 `worldbookTools`（createEntry / expandFromContext / generateKeywords）生成条目
- **AND** 每个条目生成后立即标记 `autoGenerated: true` 写入草稿区（不直接成为正式条目）
- **AND** 每生成 3-5 个条目后触发一次微型审计（复用 `worldbookAuditService`），发现问题注入 steer 消息自我修正
- **AND** 通过 `progress` 回调实时推送进度（当前维度 / 总维度 / 已生成条目数 / 当前活动）

#### Scenario: 审计闭环阶段自动修复或提示
- **WHEN** 所有维度编写完成或达到目标条目数
- **THEN** 智能体进入 `AUDITING` 状态，执行完整审计：
  - 内容完整性校验（必填字段、维度覆盖、条目数达标）
  - 逻辑一致性检查（关键词不冲突、设定无矛盾、关系图无环）
  - 设定符合度评估（与用户初始提示 + 澄清回答的语义一致性，复用向量检索）
- **AND** 审计通过则进入 `AWAITING_REVIEW` 状态；审计发现问题则自动修复（小问题）或汇总报告提示用户（大问题）
- **AND** 最终进入 `AWAITING_REVIEW`，等待用户在 `WorldBookAutoGeneratedReview` 待审阅区审批草稿条目

### Requirement: 智能体自驱扩展能力
系统 SHALL 在 PLANNING 与 AUTHORING 阶段实现自驱扩展，不依赖用户逐步指令。

#### Scenario: 主动扩展内容维度
- **WHEN** 智能体在 PLANNING 阶段分析用户初始提示
- **THEN** 主动识别用户未提及但对世界书完整性必要的维度（如用户说"侦探小说"但未提及"犯罪组织"，智能体应主动建议补充"地下势力"维度）
- **AND** 在 `AuthoringPlan` 中标注哪些维度是"用户明确要求"、哪些是"智能体建议补充"

#### Scenario: 主动提出澄清问题
- **WHEN** 智能体识别到提示中的模糊点或缺失关键信息
- **THEN** 提出 2-4 个结构化澄清问题（每问题附"为什么需要这个信息"的说明）
- **AND** 用户可选择回答或跳过；跳过的维度由智能体自主决定默认值并标注"智能体推断"

#### Scenario: 逻辑自洽性检查
- **WHEN** AUTHORING 阶段生成新条目时
- **THEN** 智能体调用 `worldbookAuditService.checkConsistency` 对比已有条目，检测矛盾（如条目A说"城市在地下"，条目B说"摩天大楼林立"）
- **AND** 发现矛盾时注入 steer 消息触发自我修正，或跳过该条目并在审计报告中标记

### Requirement: 编写过程审计机制
系统 SHALL 提供独立的审计服务 `worldbookAuditService`，对编写过程与结果进行三维度质量把控。

#### Scenario: 内容完整性校验
- **WHEN** 审计服务执行 `validateCompleteness(plan, entries)`
- **THEN** 校验每个条目的必填字段（`key` 非空数组、`content` 非空、`comment` 或 `name` 非空）
- **AND** 校验维度覆盖（`AuthoringPlan` 中每个维度至少有 1 个条目）
- **AND** 校验条目数达标（每维度达到目标条目数的 80% 以上）
- **AND** 返回 `CompletenessReport`（缺失字段列表、未覆盖维度、未达标维度）

#### Scenario: 逻辑一致性检查
- **WHEN** 审计服务执行 `checkConsistency(entries)`
- **THEN** 检测关键词冲突（同一 `key` 触发语义矛盾的条目，复用向量检索 cosine 相似度）
- **AND** 检测设定矛盾（通过 LLM 对比条目 content 的语义一致性）
- **AND** 检测关系图无环（若条目间有 `relations` 字段，校验无循环依赖）
- **AND** 返回 `ConsistencyReport`（冲突条目对列表、矛盾描述、严重级别）

#### Scenario: 设定符合度评估
- **WHEN** 审计服务执行 `evaluateConformance(userPrompt, clarifications, entries)`
- **THEN** 将用户初始提示 + 澄清回答向量化，与每个条目做 cosine 相似度检索
- **AND** 低相似度条目标记为"偏离设定"，附相似度分数
- **AND** 返回 `ConformanceReport`（符合条目数 / 总条目数、偏离条目列表）

### Requirement: Agent 模式硬约束
系统 SHALL 严格遵循 Agent 模式 gating，关闭时智能体完全不可用。

#### Scenario: Agent 模式关闭时入口隐藏
- **WHEN** `useAgent === false`（默认）或 `supportsToolCalling === false`
- **THEN** `WorldBookManager` 不显示"智能体编写"按钮
- **AND** `worldbookAgent:*` IPC 通道处理器返回 `{ ok: false, error: 'AGENT_MODE_DISABLED' }`

#### Scenario: Agent 模式开启时入口可用
- **WHEN** `useAgent === true && supportsToolCalling === true`
- **THEN** `WorldBookManager` 显示"智能体编写"按钮（RobotOutlined 图标，与"待审阅"按钮并列）
- **AND** 点击后打开 `WorldBookAuthoringModal`

#### Scenario: 非 Agent 模式手动编写不受影响
- **WHEN** Agent 模式关闭
- **THEN** `WorldBookManager` 的手动 CRUD、`WorldBookEntryEditor` 编辑、`WorldBookAIGenerateFlow` AI 生成流程全部正常工作
- **AND** `worldBookService.ts` 核心 CRUD 方法行为零变化

### Requirement: 断点续跑与取消
系统 SHALL 支持编写过程的中断恢复与主动取消。

#### Scenario: 断点续跑
- **WHEN** 编写过程中进程退出或用户关闭 Modal
- **THEN** `AuthoringSession` 状态已持久化到 MemoryStore（含当前状态、已完成维度、已生成条目 ID 列表）
- **AND** 重新打开 Modal 时显示"继续上次编写"选项，恢复到中断点

#### Scenario: 主动取消
- **WHEN** 用户点击"取消"按钮
- **THEN** 通过 `AbortController` 中止当前 LLM 调用，停止后续维度生成
- **AND** 已生成的草稿条目保留在待审阅区，用户可选择审批或批量删除

### Requirement: 进度回调与事件流
系统 SHALL 通过 IPC 事件流实时推送编写进度。

#### Scenario: 进度推送
- **WHEN** 编写过程进行中
- **THEN** 通过 `worldbookAgent:progress` 事件推送 `{ phase, currentDimension, totalDimensions, entriesGenerated, targetEntries, currentActivity, message }`
- **AND** 前端 `useWorldBookAuthoring` hook 订阅事件流更新 UI（进度条 + 事件日志 + 当前活动提示）

### Requirement: 与现有底座集成
系统 SHALL 复用现有智能体底座能力，不重复造轮子。

#### Scenario: 复用 worldbookTools 工具能力
- **WHEN** 智能体需要创建条目 / 扩展上下文 / 生成关键词 / 排序条目
- **THEN** 调用 `src/main/services/agent/tools/builtin/worldbookTools.ts` 已实现的工具（不重新实现）
- **AND** 通过 `ToolCallContext.mode = 'worldbook'` + `allowedWorldBookPaths` 沙盒白名单约束写入范围（复用 Task 17 沙盒机制）

#### Scenario: 复用 MemoryStore 持久化
- **WHEN** 智能体需要保存会话状态 / 编写过程记忆
- **THEN** 调用 `memoryStore.write` + `writeProvenance`（source: 'worldbook-agent', runId, toolName, timestamp）
- **AND** 审计报告也持久化到 MemoryStore，便于后续追溯

#### Scenario: 注册为内置技能
- **WHEN** Agent 模式开启且技能注册表初始化
- **THEN** `worldbook-author` 技能注册到 `skillRegistry`（`userInvocable: true`, `disableModelInvocation: true`）
- **AND** 技能快照通过 `skillSnapshot.buildSkillSnapshot` 注入到 agent prompt 的 `<available_skills>` 中
