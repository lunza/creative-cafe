# 智能体自由流式工作模式 Spec

## Why

当前世界书编写智能体采用程序化三阶段状态机（PLANNING→AUTHORING→AUDITING），通过 `worldBookAgent.run` IPC 阻塞调用 + 进度事件推送模式工作，智能体的思考过程和生成内容被进度面板截断展示（120/200/300 字符），用户无法看到完整输出。这种程序化工作流限制了智能体的灵活性，且非流式输出导致用户体验与角色卡对话差距巨大。需要将世界书编写改为通过 `agent.run` 流式对话模式工作，移除所有预设工作流限制和输出截断，仅通过 skill 系统控制数据入库格式。

## What Changes

- **移除 `/编写` 指令的专用 IPC 路径**：`handleWriteWorldbook` 不再调用 `worldBookAgent.run` / `worldBookAgent.onProgress` / `worldBookAgent.answer`，改为直接走 `agent.run` 流式对话路径
- **移除进度面板机制**：删除 `buildAuthoringProgressPanel` 函数、`_progressPanelId` 消息标识、`worldbookWriting` 状态、进度面板 loading 指示器
- **移除逐项提问弹窗**：删除 `clarifyState` / `handleClarifyAnswer` / `AgentQuestionModal` 组件集成，智能体通过流式对话自然提问
- **移除输出截断**：删除所有 `.slice(0, N)` 截断逻辑（思考步骤摘要 120/300 字符、生成条目内容 200 字符）
- **skill 系统控制入库格式**：更新 `worldbook-author` SKILL.md，将数据入库格式规范（条目结构、字段要求、autoGenerated 标记）写入技能契约，通过 `skill.getPromptSnippet` 注入 systemPrompt
- **流式输出体验**：`/编写` 指令改为追加 user 消息后直接走 `sendMessage` 的 `agent.run` 流式路径，与角色卡对话体验完全一致

## Impact

- Affected specs: `implement-worldbook-authoring-agent`（移除状态机工作流）、`add-worldbook-thinking-visualization`（移除进度面板）、`enhance-agent-worldbook-content-visibility`（移除内容截断）、`optimize-agent-question-interaction`（移除逐项提问弹窗）、`add-assist-mode-options`（辅助模式保留）
- Affected code:
  - `src/renderer/components/AgentCenter/hooks/useAgentDialogue.ts` — 重写 `handleWriteWorldbook`，移除进度面板/截断/逐项提问逻辑
  - `src/renderer/components/AgentCenter/AgentDialogueModal.tsx` — 移除 AgentQuestionModal 集成、Loading 指示器
  - `src/main/services/agent/skills/builtin-skills/worldbook-author/SKILL.md` — 更新为流式工作模式 + 数据入库格式规范
  - `src/shared/types/worldbook-authoring.types.ts` — `AuthoringProgressEvent` 的 `generatedEntries` / `auditDetail` / `thoughtStep` 字段保留但不再使用（向后兼容）

## ADDED Requirements

### Requirement: 流式编写工作模式

系统 SHALL 在用户执行 `/编写` 指令时，将世界书编写请求作为普通对话消息通过 `agent.run` 流式路径发送，而非通过专用 `worldBookAgent.run` IPC 阻塞调用。智能体的所有思考过程、生成内容、工具调用结果通过 token 流实时推送到对话框，与角色卡对话体验完全一致。

#### Scenario: /编写 指令流式执行
- **WHEN** 用户输入 `/编写 神秘别墅.json，有任何问题随时问我`
- **THEN** 系统解析出世界书名称和附加上下文
- **AND** 将用户消息追加到对话框
- **AND** 构建 systemPrompt（含 worldbook-author 技能格式规范 + 世界书路径上下文）
- **AND** 通过 `agent.run` 流式发送，token 实时推送到对话框
- **AND** 智能体自主决定工作流程（收集信息、生成条目、审计等）

#### Scenario: 智能体自主提问
- **WHEN** 智能体在流式输出中向用户提出问题
- **THEN** 问题直接在对话框中展示（流式文本）
- **AND** 用户可直接在输入框回复，无需弹窗
- **AND** 回复继续通过 `agent.run` 流式发送

### Requirement: skill 系统控制数据入库格式

系统 SHALL 通过 `worldbook-author` 技能的 SKILL.md 定义世界书条目的数据入库格式规范，并通过 `skill.getPromptSnippet` 注入到 `agent.run` 的 systemPrompt 中。智能体在生成条目时必须遵守此格式规范。

#### Scenario: 格式规范注入
- **WHEN** 构建 `agent.run` 的 systemPrompt
- **THEN** 调用 `skill.getPromptSnippet` 获取 worldbook-author 技能的格式规范片段
- **AND** 将格式规范追加到 systemPrompt 中
- **AND** 格式规范包含：条目结构（name/content/keys/secondaryKeys/comment/dimensionId）、autoGenerated 标记要求、worldBookPath 参数传递方式

### Requirement: 无截断完整输出

系统 SHALL 禁止对智能体的输出内容施加任何形式的截断处理，确保完整呈现所有思考过程和结果。token 流直接累加到对话框消息内容，不做任何长度限制。

#### Scenario: 完整流式输出
- **WHEN** 智能体通过 `agent.run` 生成内容
- **THEN** 每个 token chunk 直接累加到 assistant 消息的 content
- **AND** 不存在任何 `.slice(0, N)` 截断逻辑
- **AND** 用户可滚动查看完整输出

### Requirement: 无遮挡对话界面

对话框界面 SHALL 不包含任何遮挡元素（弹窗、遮罩层、进度面板覆盖等），保证用户能够清晰查看全部内容。所有交互（包括智能体提问和用户回答）均在对话框内完成。

#### Scenario: 纯对话框交互
- **WHEN** 智能体执行世界书编写
- **THEN** 所有内容展示在对话框消息流中
- **AND** 不弹出任何 Modal / 弹窗 / 遮罩层
- **AND** 用户输入框始终可用（非 streaming 时）

## MODIFIED Requirements

### Requirement: worldbook-author 技能契约

`worldbook-author` SKILL.md SHALL 从"三阶段启发式工作流"改为"自由流式工作模式 + 数据入库格式规范"。技能描述更新为流式对话模式，工作流程不再预设阶段，仅保留数据入库格式要求。

### Requirement: handleWriteWorldbook 实现

`handleWriteWorldbook` SHALL 不再调用 `worldBookAgent.run` / `worldBookAgent.onProgress` / `worldBookAgent.answer`，改为构建 systemPrompt（含技能格式规范 + 世界书路径）后直接走 `agent.run` 流式路径。

## REMOVED Requirements

### Requirement: 三阶段状态机工作流
**Reason**: 用户要求完全移除预设工作路线，允许智能体以非程序化方式灵活运作
**Migration**: `worldbookAuthoringService` 保留但不再从智能体对话框调用，仅 `WorldBookAuthoringModal` 独立入口可使用

### Requirement: 进度面板实时更新
**Reason**: 进度面板截断展示内容，且非流式更新，与用户要求的"实时流式输出"冲突
**Migration**: 移除 `buildAuthoringProgressPanel`、`_progressPanelId`、`worldbookWriting` 状态

### Requirement: 逐项提问弹窗
**Reason**: 弹窗遮挡对话框，与用户要求的"对话框界面不得包含任何遮挡元素"冲突
**Migration**: 移除 `clarifyState` / `handleClarifyAnswer` / `AgentQuestionModal` 集成，智能体通过流式对话自然提问

### Requirement: 输出内容截断
**Reason**: 用户要求"禁止对智能体的输出内容施加任何形式的截断处理"
**Migration**: 移除所有 `.slice(0, N)` 截断逻辑
