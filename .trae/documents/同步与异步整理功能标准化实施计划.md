## 待完成任务

### 步骤 1：提取 processMessagesCore 核心处理逻辑
**目标**：将同步整理和异步整理中重复的消息处理循环提取为独立私有方法

**当前状态**：processChatProgressive 和 processChatFull 的 for 循环内部代码（构建上下文、构建提示词、调用 AI、解析命令、执行命令、保存进度）仍有重复。

**实施方案**：
1. 创建新方法 `processMessagesCore`，参数包括：
   - messages: 消息数组
   - startIndex: 起始索引
   - aiConfig: AI 配置
   - apiEndpoint: API 端点
   - signal: AbortSignal（可选）
   - chatId, safeChatId, roleCardName, memoryDir 等上下文信息
   - logger: 日志前缀
2. 核心循环逻辑：
   - 构建上下文（buildContextFromMessages）
   - 构建提示词（buildOrganizePrompt）
   - 调用 AI（callAIAPI with signal）
   - 解析命令（parseJsonCommands）
   - 执行命令并保存表格数据
   - 进度保存（process-*.json）
3. 返回值：{ success: boolean, error?: string, lastProcessedIndex: number }

### 步骤 2：重构 processChatProgressive 调用核心方法
**变更内容**：
1. 保留差异化逻辑：

   - 增量更新进度文件
2. 删除重复的核心循环代码，替换为调用 `this.processMessagesCore()`
3. 保持通知发送和错误回滚逻辑

### 步骤 3：重构 processChatFull 调用核心方法
**变更内容**：

   - 从 startIndex = 0 开始
2. 删除重复的核心循环代码，替换为调用 `this.processMessagesCore()`
3. 保持 AbortController 信号传递

### 步骤 4：添加统一的后处理流程
**目标**：整理完成后自动创建表格快照和版本记录

**实施方案**：
1. 创建 `postProcessOrganize` 私有方法：
   - 参数：chatId, roleCardName, memoryDir, finalTableData, organizeType（'sync' | 'full'）
   - 读取或创建 version-index.json
   - 调用 VersionLinkerService.createLinkedVersion 创建关联版本
   - 调用 TableSnapshotService.createSnapshot 创建表格快照
   - 更新 process JSON 标记完成状态
2. 在 processChatProgressive 和 processChatFull 成功完成后调用此方法
3. 确保后处理失败不影响主流程（仅记录警告日志）

### 步骤 5：统一性能指标记录
**目标**：在两个方法中添加一致的性能监控

**实施方案**：
1. 在方法开始记录 startTime = Date.now()
2. 在方法结束时记录处理时长、处理消息数量
3. 统一日志格式：
   ```
   [TableOrganize][Sync] Performance: processed 15 messages in 3245ms, 216ms/message
   [TableOrganize][Full] Performance: processed 42 messages in 8932ms, 212ms/message
   ```
