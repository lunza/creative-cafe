# 统一聊天对话框组件计划

## 背景分析

当前系统中有两个使用 CharacterDialogueChat 对话框的入口点：

### 入口点 1: CharacterManager (角色卡管理)
- 位置: `src/renderer/components/Character/CharacterManager.tsx`
- 触发方式: 点击角色卡列表中的"对话"按钮
- 数据流: 角色卡列表 → handleTestCharacter → 设置 testChatCharacter/testChatAvatar → 渲染 CharacterDialogueChat
- 特点: 直接传入角色卡信息，支持角色卡选择面板

### 入口点 2: ChatMode (聊天模式)
- 位置: `src/renderer/components/Chat/ChatMode.tsx`
- 触发方式: 点击 ChatModule 中的"聊天模式"面板
- 数据流: isDialogMode=true → 自动加载第一个角色卡 → 设置 characterInfo → 渲染 CharacterDialogueChat
- 特点: 使用独立的状态管理 (characterChatStore)，有自己的角色加载逻辑

## 问题
- 两个入口点各自维护角色加载逻辑，存在代码重复
- 状态管理分散（CharacterManager 使用本地 state，ChatMode 使用 characterChatStore）
- 未来修改对话框功能时需要同时修改两处
- 用户体验不一致（ChatMode 缺少角色卡选择面板）

## 解决方案

### 方案概述
创建一个统一的 `UnifiedChatDialog` 组件，封装所有对话框逻辑，两个入口点都使用这个统一组件。

### 统一组件设计

#### 组件名称
`UnifiedChatDialog`

#### 文件位置
`src/renderer/components/Chat/UnifiedChatDialog.tsx`

#### 核心职责
1. 接收角色卡信息（Character 或 CharacterInfo）
2. 处理角色卡加载（读取文件、解析信息、加载头像）
3. 管理对话框状态（打开/关闭）
4. 渲染 CharacterDialogueChat 并传递所有必要的 props
5. 支持角色卡选择面板（可选）
6. 统一加载状态和错误处理

#### Props 接口
```typescript
interface UnifiedChatDialogProps {
  // 对话框显示控制
  open: boolean;
  onClose: () => void;
  
  // 角色卡信息（二选一）
  initialCharacter?: Character;  // 直接传入角色卡对象
  initialCharacterPath?: string; // 传入角色卡路径
  
  // 可选配置
  showCharacterSelector?: boolean;  // 是否显示角色卡选择面板
  characters?: Character[];         // 角色卡列表（用于选择面板）
  onCharacterSelect?: (character: Character) => void;  // 角色卡选择回调
  
  // 自定义头像路径（可选覆盖默认加载逻辑）
  avatarPath?: string;
}
```

## 实施步骤

### 步骤 1: 创建统一对话框组件
**文件**: `src/renderer/components/Chat/UnifiedChatDialog.tsx`

创建新组件，封装以下逻辑：
1. 接收 props 并处理角色卡加载
2. 使用 useCharacterSwitch hook 处理角色切换
3. 管理内部状态（characterInfo, avatarPath, loading）
4. 渲染 CharacterDialogueChat 并传递所有 props
5. 处理加载状态和错误状态
6. 支持角色卡选择面板

**关键实现**:
- 使用 useEffect 监听 initialCharacter/initialCharacterPath 变化
- 调用 useCharacterSwitch.switchCharacter() 加载角色
- 维护本地状态避免与外部 store 冲突
- 支持角色卡选择时立即切换（通过 onCharacterSelect 回调）

### 步骤 2: 重构 CharacterManager 使用统一组件
**文件**: `src/renderer/components/Character/CharacterManager.tsx`

修改内容：
1. 导入 UnifiedChatDialog 替代 CharacterDialogueChat
2. 移除本地的 handleTestCharacter 逻辑（保留调用）
3. 传递简化的 props 给 UnifiedChatDialog
4. 移除本地的 testChatCharacter/testChatAvatar 状态管理

**修改前**:
```tsx
<CharacterDialogueChat
  characterInfo={testChatCharacter}
  open={isTestChatOpen}
  onClose={...}
  avatarPath={testChatAvatar}
  characters={characters}
  onCharacterSelect={handleTestCharacter}
/>
```

**修改后**:
```tsx
<UnifiedChatDialog
  open={isTestChatOpen}
  onClose={...}
  initialCharacter={selectedCharacter}
  showCharacterSelector={true}
  characters={characters}
  onCharacterSelect={handleCharacterSwitch}
/>
```

### 步骤 3: 重构 ChatMode 使用统一组件
**文件**: `src/renderer/components/Chat/ChatMode.tsx`

修改内容：
1. 移除本地的角色加载逻辑（loadCharacter 函数）
2. 使用 UnifiedChatDialog 替代 CharacterDialogueChat
3. 传递 initialCharacterPath 或 initialCharacter
4. 简化状态管理

**修改前**:
```tsx
<CharacterDialogueChat
  characterInfo={activeCharacterInfo}
  open={isDialogMode === true}
  onClose={handleClose}
  avatarPath={(activeCharacterInfo as any)?.avatarPath}
/>
```

**修改后**:
```tsx
<UnifiedChatDialog
  open={isDialogMode === true}
  onClose={handleClose}
  initialCharacterPath={characters[0]?.path}
  showCharacterSelector={true}
  characters={characters}
  onCharacterSelect={handleCharacterSwitch}
/>
```

### 步骤 4: 增强 CharacterDialogueChat 的类型定义
**文件**: `src/renderer/components/Character/CharacterDialogueChat/CharacterDialogueChat.types.ts`

添加或确认类型兼容性，确保 UnifiedChatDialog 和 CharacterDialogueChat 之间的类型传递正确。

### 步骤 5: 统一导出
**文件**: 
- `src/renderer/components/Chat/index.ts` (新建或更新)
- `src/renderer/components/Character/CharacterDialogueChat/index.ts`

确保统一组件正确导出，两个模块都可以方便地导入使用。

### 步骤 6: 验证和测试
1. 运行 typecheck 确保类型正确
2. 验证 CharacterManager 中的对话框功能正常
3. 验证 ChatMode 中的对话框功能正常
4. 验证角色卡选择面板在两个入口点都能正常工作
5. 验证角色切换功能正常

## 技术要点

### 状态管理策略
- UnifiedChatDialog 维护本地状态（characterInfo, avatarPath）
- 不依赖 characterChatStore，避免状态冲突
- 通过 props 接收外部控制（open/onClose）

### 角色加载逻辑
- 复用 useCharacterSwitch hook 中的加载逻辑
- 处理图片文件和非图片文件的头像加载差异
- 处理加载失败的情况

### 角色卡选择面板
- 在 UnifiedChatDialog 内部集成 CharacterSelectorPanel
- 通过 props 控制是否显示
- 选择回调由外部传入

## 优势
1. **单一职责**: 对话框逻辑集中在一个组件
2. **代码复用**: 消除重复的角色加载逻辑
3. **易于维护**: 未来修改只需改一处
4. **一致性**: 两个入口点的用户体验完全一致
5. **可扩展**: 新的入口点可以直接使用统一组件
6. **类型安全**: 统一的类型定义和 props 接口
