# 创作中心聊天模式优化计划

> **创建日期**：2026-07-06
> **范围**：创作中心（CreationCenter）聊天模式及其全部相关功能，包括入口流程、角色对话（CharacterDialogueChat）、配置面板、向量化/知识库绑定、记忆表格等
> **目标**：从功能性 Bug、UI/视觉一致性、易用度、代码实现质量、向量化/知识库合理性五个维度进行全面审查与优化

---

## 一、当前状态分析

### 1.1 架构链路

```
CreationCenter（三面板入口：chat/creative/game）
  └─ SingleChatDialog（加载角色列表，默认 characters[0]）
       └─ UnifiedChatDialog（角色切换逻辑）
            └─ CharacterDialogueChat（Modal：角色选择器 + 聊天区 + 配置面板）
                 ├─ ChatHeader（头像/名称/收藏/导出/清空/全屏/关闭）
                 ├─ ChatMessageBubble（消息气泡 + 操作按钮）
                 ├─ ChatInputBar（输入框 + 人称选择 + AI回复 + 润色 + 发送）
                 ├─ ConfigPanel
                 │    ├─ PersonaPanel（用户人设）
                 │    ├─ ParameterPanel（AI 参数）
                 │    ├─ VectorizationPanel → KnowledgeBaseBindingPanel（知识库绑定）
                 │    ├─ MemoryTablePanel（记忆表格）
                 │    └─ TokenManagementPanel（Token 管理）
                 └─ CharacterSelectorPanel（角色选择侧栏）
```

### 1.2 主题系统现状

`src/renderer/styles/ui-variables.css` **已定义完整的双主题 CSS 变量系统**：
- `:root` 下定义了全部亮色主题变量（`--chat-dialog-bg-gradient`、`--chat-header-bg`、`--chat-input-bg` 等约 60+ 个聊天相关变量）
- `.dark` 下定义了对应的暗色覆盖值
- `App.tsx` 已实现 `document.body.classList.add/remove('dark')` 切换

**问题**：组件层未一致使用变量系统——大量内联样式硬编码深色值或使用深色 fallback，导致浅色主题下视觉破损。

## 四、假设与决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 主题适配方式 | 复用已有 `ui-variables.css` 变量系统，组件改用 `var(--xxx)` | 变量已完整定义双主题，无需新建 |
| 内联样式迁移策略 | 视觉属性迁 CSS，布局属性保留内联（React 动态计算方便） | 平衡可维护性与灵活性 |
| 公共 Dialog 组件 | 提取 `FullscreenDialog` 替代 WritingModeDialog/GameModeDialog | 消除重复，后续扩展统一 |
| 头像加载逻辑 | 提取 `loadCharacterAvatar` 工具函数 | 消除 CreationCenter 与 CharacterSelectorPanel 重复 |
| 角色搜索实现 | 前端 filter（非后端搜索） | 角色量级通常 <500，前端过滤足够，且角色列表已全量加载 |
| 检索反馈数据来源 | hook state → sessionStorage（跨面板共享） | 避免引入新 store 的复杂度 |
| 导出文件保存 | 调用 `window.electronAPI.file.write` | 已有 IPC 能力，无需新增 |
| i18n 方案 | 硬编码中文（不引入 i18n 框架） | 项目无 i18n 基础设施，本次范围不宜扩展 |
