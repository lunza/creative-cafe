# 写作模式开发补全计划

## 当前状态概览

已完成模块：类型定义、常量、Zustand Stores、数据持久层、资源管理器、类型模板、PromptBuilder、OutlineGenerator、ContentGenerator、IPC Handlers、Preload API、5个基础UI组件（Entry/List/Config/OutlineEditor/ContentWorkspace）。

**关键问题**：连续生成循环缺失、AI配置未传递、版本管理完全缺失、暂停/恢复功能缺失、上下文管理不完整。

---

## 第一阶段：关键基础设施修复

### 1.1 修复 AI 配置传递链路
- `ContentWorkspace.tsx` 使用 `writingProjectStore.getCurrentProject().config.modelConfig` 替代硬编码值
- `writing:generateChapter` IPC handler 从 request 中正确读取 projectId
- `ContentGenerator.ts` 的 `getBaseUrl/getApiKey` 使用项目配置中的模型设置

### 1.2 修复 ContentWorkspace 上下文注入
- 从项目配置读取 `worldBookIds` / `characterCardIds`
- 通过 `writing:loadResources` IPC 加载选中的世界书和角色卡
- 将资源数据填充到 `worldBookContext` / `characterContext` 传递给生成请求

### 1.3 创建 WritingEngine 统一门面
- 新建 `WritingEngine.ts` 封装 OutlineGenerator + ContentGenerator 的调用
- 重构 `writingHandlers.ts` 使用 WritingEngine 替代直接调用生成器

---

## 第二阶段：核心功能补全

### 2.1 连续生成循环
- 在 `ContentWorkspace.tsx` 实现 `handleContinuousGeneration()`
- 递归调用：当前章完成 → 自动触发下一章 → 直到所有章节完成或用户停止
- 添加"开始连续生成"按钮和进度条

### 2.2 暂停/恢复/停止控制
- 在 `ContentGenerator.ts` 实现 `isPaused` 检查逻辑（轮询等待）
- `ContentWorkspace.tsx` 添加暂停、继续按钮
- 处理 `AbortController` 的暂停语义（暂停时保持连接不断开）

### 2.3 章节版本管理
- `WritingStorageService` 新增 `saveVersion()` / `loadVersions()` / `restoreVersion()`
- `ChapterEditor` 组件：显示版本列表，支持回退
- 自动生成内容时创建 `isAutoGenerated: true` 的版本快照
- 手动编辑后保存为手动版本

---

## 第三阶段：UI 组件完善

### 3.1 资源选择器增强
- `WritingConfigPanel` 中添加搜索框（世界书/角色卡名称搜索）
- 已选资源卡片式展示，支持单独移除
- 点击资源名称显示预览 Tooltip（描述/条目数/标签）

### 3.2 项目列表增强
- 添加搜索框（按名称过滤）
- 添加状态筛选器（全部/草稿/大纲/创作中/已完成）
- 添加删除按钮（带确认弹窗）

### 3.3 进度与状态指示
- `WritingProgressBar.tsx`：显示整体进度（已完成/总章节数）
- `WritingStatusIndicator.tsx`：显示当前生成状态（空闲/生成中/已暂停/错误）
- 字数统计显示在章节导航中

---

## 第四阶段：上下文管理完善

### 4.1 长期上下文
- `ContentGenerator.buildLongTermContext()` 从空实现改为加载：
  - 角色档案摘要
  - 世界观核心规则
  - 已埋设伏笔列表（从 metadata.continuityInfo 读取）

### 4.2 连贯性约束增强
- `PromptBuilder.buildContinuityConstraints()` 使用实际的伏笔/角色发展数据
- 在 `handleGenerateChapter` 中传递 `metadata.continuityInfo`

### 4.3 上下文 Token 预算控制
- 实现 `compressContextIfNeeded()` 方法
- 当总 token 接近限制时按优先级压缩上下文

---

## 第五阶段：错误处理与容错

### 5.1 错误恢复 UI
- 生成失败时显示重试按钮
- 区分可恢复错误和不可恢复错误

### 5.2 自动重试机制
- 网络超时自动重试（最多3次）
- 重试间隔递增（1s, 2s, 4s）

### 5.3 用户取消优雅处理
- 区分 AbortError 和真正的错误
- 取消时设置 `USER_CANCELLED` 状态

---
