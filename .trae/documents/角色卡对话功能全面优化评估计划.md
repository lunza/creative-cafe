# 角色卡对话功能全面优化评估计划

## 概述

本计划对角色卡对话功能（CharacterDialogueChat）进行三个维度的全面评估与优化：视觉样式、AI参数配置系统、对话内容增强设计。基于对现有代码的深入分析，提供详细的建议清单和实施方案。

---

## 一、现状分析

### 1.1 视觉样式现状

**CSS 变量体系**：已建立完善的双主题系统（`ui-variables.css`），通过 `:root`（亮色）和 `.dark`（暗色）类选择器切换，定义了 ~40 个聊天相关 CSS 变量。

**核心问题**：
1. **主题选择器不一致**：`MessageRenderer.styles.css` 中引号高亮使用 `[data-theme="dark"]`/`[data-theme="light"]`，而全局系统使用 `.dark` 类 → 暗色主题下引号高亮颜色可能无法正确匹配
2. **大量内联样式**：`ChatMessageBubble.tsx`（617行）几乎所有样式都内联在 JSX 中，硬编码颜色值如 `#6366f1`、`#8b5cf6`、`rgba(0,0,0,0.15)` 等遍布全文
3. **无交替背景色**：消息列表无交替背景，长对话阅读疲劳
4. **辅助模式选项样式**（`ChatMessageBubble.css`）中 `rgba(255,255,255,0.55)` 等颜色在亮色主题下几乎不可见

### 1.2 AI 参数配置现状

**两层参数体系**：
- 全局层：系统设置 `AIEngineSettingsPanel.tsx` -> `AIEngineSetting`（`setting.ts` 第197-387行），包含 30+ 参数
- 角色层：`ParameterPanel.tsx` -> `AIParameterConfig`（`types.ts` 第99-181行），包含 10 个采样参数 + 5 个功能开关
- 合并逻辑：`useCharacterConfig.getEffectiveParams()` 按三级优先级合并（自定义 > 全局引擎 > 硬编码默认值）

**核心问题**：
1. **参数重叠**：`temperature`、`max_tokens`、`top_p`、`frequency_penalty`、`presence_penalty` 在两处都可配置，用户困惑
2. **系统设置中的冗余参数**：`AIEngineSetting` 包含大量 SillyTavern 风格参数（`top_k`、`top_a`、`min_p`、`tfs`、`epsilon_cutoff`、`eta_cutoff`、`typical_p`、`penalty_alpha`、`mirostat_mode/tau/eta` 等）但角色面板中不可配置，且大部分未在 `buildSamplingExtras` 中使用
3. **角色面板缺少关键参数**：`top_k`、`min_p` 在系统设置中存在但角色面板不暴露
4. **功能开关混杂**：`expression_display`、`strip_think_tags`、`assist_mode`、`language` 等非采样参数与采样参数混在同一面板

### 1.3 对话内容增强现状

**当前单一处理方式**：
- 引号高亮：`rehype-quote-highlight.ts` + `rehype-quote-normalize.ts` 将所有引号内容包裹在带 `message-renderer-quote-highlight` class 的 span 中
- 颜色：默认 `#FFB347`（橙黄）、暗色 `#FFCA28`（金黄）、亮色 `#E65100`（深橙）
- 效果：加粗(font-weight 600) + 文字阴影(text-shadow)

**辅助模式选项中的区分**（仅限推荐选项，非对话主体）：
- `()` 包裹 -> `suggested-option-action`：斜体 + 半透明色
- `""` 包裹 -> `suggested-option-dialogue`：高亮色

**缺失的内容增强**：
- 思考内容：`stripThinkingTags()` 直接移除所有 `<think>` 标签内容，用户无法看到 AI 思考过程
- 角色名：12px 灰色文字，无突出显示
- 行为描述：`*action*` 或 `_action_` 仅渲染为斜体，无背景/边框区分
- 对话气泡：仅圆角和背景色差异，无系统化的形状/阴影/边框差异化
- 消息背景：无交替色、无纹理、无区域分隔

#### C. 参数分类方案与界面布局建议

**建议将 `ParameterPanel.tsx` 重组为 4 个分区**：

```
┌─────────────────────────────────┐
│  采样参数                        │  <- 核心参数区
│  - Temperature      [滑块]      │
│  - Top-P            [滑块]      │
│  - Freq Penalty     [滑块]      │
│  - Pres Penalty     [滑块]      │
│  - 防重复强度       [宽松/标准/严格] │
├─────────────────────────────────┤
│  回复控制                        │  <- 回复约束区
│  - Min Response Chars [滑块]    │
│  - Custom Stop Sequences [开关+文本] │
├─────────────────────────────────┤
│  显示设置                        │  <- 非采样参数
│  - 表情显示         [开关]       │
│  - Think标签处理    [开关]       │
│  - 辅助模式         [开关]       │
│  - 回复语言         [下拉]       │
├─────────────────────────────────┤
│  高级采样参数（折叠）             │  <- 高级区
│  - Repetition Penalty [滑块]    │
│  - Top-K             [滑块]     │  <- 新增
│  - Min-P             [滑块]     │  <- 新增
│  - DRY Multiplier    [滑块]     │
│  - DRY Base          [滑块]     │
│  - DRY Allowed Length [滑块]    │
│  - No Repeat Ngram   [滑块]     │
└─────────────────────────────────┘
```

**全局 vs 角色参数分离原则**：

| 全局配置（系统设置） | 角色配置（ParameterPanel） |
|---------------------|--------------------------|
| API 连接（url, key, model） | Temperature |
| API 模式（chat/completion） | Top-P |
| 能力探测（capabilities） | Frequency/Presence Penalty |
| 系统提示词 | 防重复强度预设 |
| 超时设置 | Min Response Chars |
| 思维链/工具调用开关 | Custom Stop Sequences |
| Max Tokens（建议移至全局） | 显示设置（表情/Think/语言） |
| 流式输出 | 辅助模式 |
| 高级采样（top_k, min_p 等全局默认值） | 高级采样覆盖（可选） |

### 2.3 对话内容增强设计清单

#### A. 角色思考内容特殊 UI 标记

**现状**：`stripThinkingTags()` 直接移除所有 `<think>`/`<thinking>`/`<thought>` 标签内容，用户无法看到 AI 的思考过程。

**设计方案**：

| 元素 | 样式规范 | 实现方式 |
|------|----------|----------|
| 思考容器 | 背景 `rgba(148, 163, 184, 0.08)`，左边框 `3px solid rgba(148, 163, 184, 0.3)`，圆角 `0 6px 6px 0`，padding `8px 12px`，margin `4px 0` | 新增 CSS 类 `.message-renderer-thought-block` |
| 思考文字 | 斜体，字号 `0.9em`，颜色 `var(--mr-thought-color)`（暗色 `#9ca3af`，亮色 `#6b7280`），行高 `1.5` | 继承容器样式 |
| 折叠交互 | 默认折叠，点击展开；展开后可再次折叠 | 使用 `<details>` 元素 + 自定义 `<summary>` |
| 开关控制 | `ParameterPanel` 新增"显示思考过程"开关（与现有 `stripThinkTags` 联动：开启=显示折叠，关闭=移除） | 修改 `stripThinkingTags` 为可选保留模式 |

**CSS 变量定义**（添加到 `ui-variables.css`）：
```css
/* 暗色主题 */
--mr-thought-bg: rgba(148, 163, 184, 0.08);
--mr-thought-border: rgba(148, 163, 184, 0.3);
--mr-thought-color: #9ca3af;

/* 亮色主题 */
--mr-thought-bg: rgba(100, 116, 139, 0.06);
--mr-thought-border: rgba(100, 116, 139, 0.25);
--mr-thought-color: #6b7280;
```

#### B. 角色名称突出显示方案

**现状**：角色名 12px 灰色文字（`var(--text-secondary, #6b7280)`），与时间戳、序号同等视觉权重。

**设计方案**：

| 方案 | 样式规范 | 适用场景 |
|------|----------|----------|
| **方案 A（推荐）**：加粗 + 主题色 | font-weight `600`，font-size `13px`，color `var(--chat-character-name-color)`（暗色 `#a78bfa` 紫色，亮色 `#7c3aed`） | 默认方案 |
| **方案 B**：彩色标签 | 背景 `rgba(139, 92, 246, 0.12)`，padding `2px 8px`，圆角 `10px`，font-weight `500` | 可选，更突出 |
| **方案 C**：字号放大 | font-size `14px`（与正文同），font-weight `600`，color `var(--text-primary)` | 最轻量 |

**用户名**：保持当前样式但加粗：font-weight `500`，color `var(--chat-username-color)`（暗色 `#818cf8`，亮色 `#4f46e5`）

**CSS 变量定义**（添加到 `ui-variables.css`）：
```css
/* 暗色主题 */
--chat-character-name-color: #a78bfa;
--chat-username-color: #818cf8;

/* 亮色主题 */
--chat-character-name-color: #7c3aed;
--chat-username-color: #4f46e5;
```

#### C. 角色行为描述视觉区分方式

**现状**：`*动作*` 和 `_动作_` 渲染为斜体，无背景或边框区分。

**设计方案**：

| 元素 | 样式规范 | CSS 类名 |
|------|----------|----------|
| 行为描述容器 | 斜体，背景 `rgba(168, 85, 247, 0.06)`，左右 padding `8px`，圆角 `4px`，颜色 `var(--mr-action-color)`（暗色 `#c4b5fd`，亮色 `#6d28d9`） | `.message-renderer-action` |
| 行为描述前缀图标 | 可选：图标前缀，font-size `0.85em`，margin-right `4px`，opacity `0.7` | `::before` 伪元素 |

**实现方式**：
- 对 `MessageRenderer.tsx` 中 `em` 元素的组件映射添加 `className="message-renderer-action"`
- 在角色对话语境中，斜体几乎都表示行为描述，统一应用行为描述样式

**CSS 变量定义**（添加到 `ui-variables.css`）：
```css
/* 暗色主题 */
--mr-action-bg: rgba(168, 85, 247, 0.06);
--mr-action-color: #c4b5fd;

/* 亮色主题 */
--mr-action-bg: rgba(124, 58, 237, 0.05);
--mr-action-color: #6d28d9;
```

#### D. 对话气泡差异化设计建议

**现状**：
- 用户气泡：蓝紫渐变背景 `linear-gradient(135deg, #6366f1, #8b5cf6)` + 白色文字
- AI 气泡：半透明背景（暗色 `rgba(30,30,46,0.8)` / 亮色 `rgba(255,255,255,0.9)`）+ 浅色文字
- 圆角：用户 `18px 18px 4px 18px`，AI `18px 18px 18px 4px`

**优化建议**：

| 元素 | 用户气泡 | AI 气泡 |
|------|----------|---------|
| 形状（圆角） | `18px 18px 4px 18px`（保持） | `18px 18px 18px 4px`（保持） |
| 背景 | 渐变保持 | 暗色加微妙渐变 `linear-gradient(135deg, rgba(30,30,46,0.8), rgba(40,40,60,0.8))`；亮色 `rgba(255,255,255,0.95)` |
| 阴影 | `0 4px 12px rgba(99,102,241,0.3)`（保持） | 暗色 `0 4px 16px rgba(0,0,0,0.25)`；亮色 `0 2px 8px rgba(0,0,0,0.06)` |
| 边框 | 无（渐变背景已足够） | 暗色 `1px solid rgba(255,255,255,0.06)`（保持）；亮色 `1px solid rgba(0,0,0,0.04)` |
| 最大宽度 | `75%`（保持） | `75%`（保持） |
| 悬停效果 | 阴影加深 `0 6px 16px rgba(99,102,241,0.4)` | 阴影加深 + 边框微亮 |
| 进入动画 | `fadeInUp 0.3s`（保持） | `fadeInUp 0.3s`（保持） |

#### E. 对话背景分层设计方案

**现状**：所有消息在统一的聊天背景上，无交替色或区域分隔。

**设计方案**：

| 方案 | 说明 | 实现复杂度 |
|------|------|-----------|
| **交替背景色（推荐）** | 奇数 AI 消息使用 `background: var(--chat-msg-stripe-bg)`，偶数透明 | 低 |
| **日期分隔线** | 超过 10 分钟间隔的消息间插入日期/时间分隔线 | 中 |
| **角色切换分隔** | 用户<->AI 切换时添加微妙分隔（已通过气泡间距隐式实现） | 已有 |

**交替背景色 CSS 变量**（添加到 `ui-variables.css`）：
```css
/* 暗色主题 */
--chat-msg-stripe-bg: rgba(255, 255, 255, 0.015);

/* 亮色主题 */
--chat-msg-stripe-bg: rgba(0, 0, 0, 0.015);
```

**实现方式**：在 `VirtualizedMessageList.tsx` 或 `ChatMessageBubble.tsx` 中根据消息索引奇偶性添加 CSS 类。

#### F. 引号高亮优化（现有橙色标记改进）

**现状**：所有引号内容统一使用橙色 `#FFB347` 高亮 + 加粗(font-weight 600) + 文字阴影。

**优化建议**：

| 改进项 | 说明 |
|--------|------|
| 移除文字阴影 | `text-shadow: 0 0 8px rgba(255,179,71,0.3)` 在长文本中造成视觉疲劳 -> 移除 |
| 降低加粗 | `font-weight: 600` -> `font-weight: 500`，减少视觉侵入感 |
| 调整颜色 | 默认主题改为更柔和的 `#E8A87C`（暖橙），暗色 `#F0B670`，亮色 `#D97706` |
| 增加微妙背景 | 添加 `background: rgba(255, 179, 71, 0.04)` + `padding: 0 2px` + `border-radius: 3px`，替代文字阴影 |

**修改文件**：`MessageRenderer.styles.css` 第 309-334 行

## 四、假设与决策

1. **不创建新文件**：所有样式修改在现有 CSS 文件中进行，不新增独立样式文件
2. **CSS 变量优先**：所有颜色值通过 CSS 变量定义，支持主题切换
3. **渐进式增强**：内容增强功能通过参数开关控制，默认不过度改变现有体验
4. **向后兼容**：新增 CSS 变量提供 fallback 值，不破坏现有主题
5. **`max_tokens` 移至全局**为建议项，需用户确认是否实施（涉及 `getEffectiveParams` 逻辑变更）
6. **系统设置冗余参数**暂不移除，标记为"实验性"即可，避免影响已有配置
7. **角色名突出显示采用方案 A**（加粗+主题色），除非用户另有偏好
8. **交替背景色**仅应用于 AI 消息（用户消息已有渐变背景，无需交替）

2. **主题切换验证**：在亮色/暗色主题下分别检查所有视觉元素（引号高亮、辅助模式选项、角色名、行为描述、思考内容折叠）

5. **回归测试**：确认现有功能（消息发送、编辑、导出、辅助模式、记忆表格等）不受影响
6. **GetDiagnostics**：对所有修改文件执行 TypeScript 诊断
