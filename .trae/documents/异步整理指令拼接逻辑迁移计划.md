# 异步整理模式指令拼接逻辑迁移计划

## 问题分析

### 当前实现
- `buildAsyncTableOrganizeInstructions()` 返回的指令被追加到 `role:system` 提示词末尾
- AI 可能因为系统提示词中的指令优先级较低而忽略 tableEdit 标签生成要求

### 目标实现
- 将表格整理指令从 `role:system` 迁移到 `role:user` 消息末尾
- 用户在对话框中不应看到自动拼接的指令内容
- 利用 AI 对最近输入（user message）记忆更深的特性，提高指令遵循率

## 核心改动

### 1. 修改 `CharacterDialogueChat.hooks.ts` - 在发送前拼接指令到用户消息

**文件**: `g:\AI\creative-cafe\src\renderer\components\Character\CharacterDialogueChat\CharacterDialogueChat.hooks.ts`

**改动位置**: `requestAIResponse` 函数中构建上下文消息的区域（约第 430-470 行）

**实现逻辑**:
```
1. 获取上下文消息列表（contextMessages）
2. 检测是否为异步整理模式：memoryTableOrganizeModeRef.current === 'async'
3. 如果是异步模式：
   a. 找到最后一条 role='user' 的消息
   b. 获取完整的表格整理指令（调用 buildAsyncTableOrganizeInstructions）
   c. 在最后一条用户消息的 content 末尾拼接指令
   d. 拼接后的消息仍然保持 role='user'
4. 将修改后的 contextMessages 传递给 AI engine
```

**关键细节**:
- 拼接指令仅在发送给 AI 的上下文中生效，不影响 UI 显示（因为 messages state 中的消息内容不会被修改）
- 需要同时传递 tableStructure 参数以获取完整的模板结构信息
- 只在异步模式下执行此逻辑，同步模式保持不变

### 2. 修改 `PromptBuilder.ts` - 调整 `buildFinalSystemPrompt` 行为

**文件**: `g:\AI\creative-cafe\src\renderer\components\Character\CharacterDialogueChat\PromptBuilder.ts`

**改动位置**: `buildFinalSystemPrompt` 函数（约第 348-394 行）

**实现逻辑**:
```
1. 移除 `organizeMode === 'async'` 时追加异步整理指令的逻辑
2. 保持 `buildAsyncTableOrganizeInstructions` 函数不变（供 hooks.ts 调用）
3. 函数签名保持不变（organizeMode 和 tableStructure 参数保留但不再在 system prompt 中使用）
```

### 3. 新增辅助函数或调整现有函数

**选项 A（推荐）**: 在 `usePromptBuilder.ts` 中新增一个导出函数 `buildAsyncTableOrganizeInstructions`，直接调用 `PromptBuilder.ts` 中的同名函数

**选项 B**: 在 `CharacterDialogueChat.hooks.ts` 中直接 import `buildAsyncTableOrganizeInstructions` 函数

**选择**: 选项 B 更简洁，直接在 hooks.ts 中导入即可

## 详细实施步骤

### Step 1: 在 `CharacterDialogueChat.hooks.ts` 中导入异步指令构建函数
- 在文件顶部添加导入：`import { buildAsyncTableOrganizeInstructions } from './PromptBuilder';`
- 注意：`buildAsyncTableOrganizeInstructions` 当前是私有函数，需要改为 `export`

### Step 2: 修改 `PromptBuilder.ts` 导出异步指令函数
- 将 `function buildAsyncTableOrganizeInstructions` 改为 `export function buildAsyncTableOrganizeInstructions`

### Step 3: 在 `CharacterDialogueChat.hooks.ts` 中实现用户消息拼接逻辑
在 `requestAIResponse` 函数中，构建 contextMessages 之后、传递给 engine 之前：

```typescript
// 在获取 contextMessages 之后，发送给 AI 之前
let finalContextMessages = [...contextMessages];

// 异步整理模式：将表格整理指令拼接到最后一条用户消息
if (memoryTableAutoOrganizeRef.current && memoryTableOrganizeModeRef.current === 'async') {
  addLog('[CharacterDialogueChat] 异步整理模式：在用户消息末尾拼接表格整理指令', 'info');
  
  // 找到最后一条用户消息
  const lastUserMsgIndex = finalContextMessages.length - 1;
  const lastMsg = finalContextMessages[lastUserMsgIndex];
  
  if (lastMsg && lastMsg.role === 'user') {
    // 获取完整的表格整理指令
    const tableOrganizeInstructions = buildAsyncTableOrganizeInstructions(
      memoryTableData || undefined,
      tableStructure
    );
    
    // 拼接指令到用户消息末尾
    finalContextMessages[lastUserMsgIndex] = {
      ...lastMsg,
      content: lastMsg.content + tableOrganizeInstructions
    };
    
    addLog(`[CharacterDialogueChat] 指令已拼接，用户消息长度: ${lastMsg.content.length} -> ${finalContextMessages[lastUserMsgIndex].content.length}`, 'info');
  } else {
    addLog('[CharacterDialogueChat] 警告：最后一条消息不是用户消息，跳过指令拼接', 'warn');
  }
}
```

### Step 4: 修改 `buildFinalSystemPrompt` 移除异步指令追加逻辑
在 `PromptBuilder.ts` 的 `buildFinalSystemPrompt` 函数中：

```typescript
// 移除以下代码块：

if (organizeMode === 'async') {

}
```

## 风险与注意事项

1. **消息顺序**: 确保拼接指令后，user message 仍然是消息列表的最后一条
2. **指令长度**: 异步整理指令较长（约 2000+ 字符），需要注意 token 限制
3. **兼容性**: 同步模式不受影响，需要确保同步模式的逻辑保持原样
4. **日志记录**: 增加详细的日志记录，便于调试和问题排查

## 预期效果

- AI 在用户消息末尾收到完整的表格整理指令，遵循率提高
- 用户界面不受影响，看不到自动拼接的指令内容
- 异步整理功能正常工作，生成包含 tableEdit 标签的响应
