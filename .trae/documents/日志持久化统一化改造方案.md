# 日志持久化统一化改造方案

## 问题分析

系统当前存在日志持久化目录分散的问题，日志文件存储在多个不同路径中：

| 日志模块 | 当前路径生成方式 | 实际路径 |
|---------|---------------|---------|
| **AiLogger.ts** | `path.join(process.cwd(), 'logs')` | `D:\AI\creative-cafe\logs` |
| **aiHandlers.ts** | `path.join(process.cwd(), 'logs')` | `D:\AI\creative-cafe\logs`（与AiLogger重复写入同一文件） |
| **fileService.ts** | `path.join(process.cwd(), 'logs')` | `D:\AI\creative-cafe\logs` |
| **storageManager.ts** | `path.join(getAppPath('appData'), 'creative-cafe', 'logs')` | `C:\Users\a1299\AppData\Roaming\creative-cafe\logs` |
| **logStore.ts** (renderer) | Zustand persist (IndexedDB/localStorage) | 浏览器存储 |
| **chatLogService.ts** | `path.join(userDataPath, 'data', 'memories', 'chatlog')` | `C:\Users\a1299\AppData\Roaming\creative-cafe\data\memories\chatlog` |
| **tableTemplateService.ts** | `path.join(userDataPath, 'data', 'memories', 'chatlog')` | `C:\Users\a1299\AppData\Roaming\creative-cafe\data\memories\chatlog` |
| **characterChatRecordService.ts** | `path.join(getUserDataPath(), 'data', 'memories', 'chats')` | `C:\Users\a1299\AppData\Roaming\creative-cafe\data\memories\chats` |

### 根本原因
1. **多处独立实现日志配置**：`AiLogger.ts`、`aiHandlers.ts`、`fileService.ts` 各自定义了相同的 `LOG_CONFIG` 常量，使用 `process.cwd()` 作为基准路径
2. **storageManager.ts** 使用 Electron 的 `appData` 路径作为基础路径
3. **memory 相关服务** 使用 `getUserDataPath()` 作为基础路径
4. **缺乏统一的日志路径管理模块**

## 改造目标

将所有类型的日志文件集中存储至 `D:\AI\creative-cafe\logs` 目录下。

## 实施方案

### 第一步：创建统一的日志路径工具模块

**文件**: `src/main/services/logPathService.ts`

创建统一的日志路径管理模块，提供以下功能：
- 统一的日志根目录常量：`D:\AI\creative-cafe\logs`
- 获取日志目录路径的方法
- 获取特定日志文件路径的方法
- 自动创建日志目录

### 第二步：更新现有日志模块

#### 2.1 更新 `src/main/services/AiLogger.ts`
- 删除本地的 `LOG_CONFIG` 和路径函数
- 引入 `logPathService.ts` 获取统一日志路径

#### 2.2 更新 `src/main/ipc/handlers/aiHandlers.ts`
- 删除本地的 `LOG_CONFIG` 和路径函数
- 引入 `logPathService.ts` 获取统一日志路径
- 注意：此模块与 AiLogger.ts 写入同一日志文件，可考虑合并或复用 AiLogger

#### 2.3 更新 `src/main/services/fileService.ts`
- 删除本地的 `LOG_CONFIG` 和路径函数
- 引入 `logPathService.ts` 获取统一日志路径

#### 2.4 更新 `src/main/services/storageManager.ts`
- 将 LOGS 目录从 `appData/creative-cafe/logs` 改为统一日志路径
- 更新 `initializeBaseDirectories()` 方法中的 logs 目录创建逻辑

#### 2.5 更新 `src/main/services/memory/chatLogService.ts`
- 此服务的 `chatlogDir` 是业务数据存储目录（存储表格数据），非系统日志
- **无需修改**，但需在计划中明确区分

#### 2.6 更新 `src/main/services/memory/tableTemplateService.ts`
- 同上，`chatlogDir` 是业务数据存储
- **无需修改**

#### 2.7 更新 `src/main/services/memory/characterChatRecordService.ts`
- 同上，`chats` 目录是业务数据存储
- **无需修改**

### 第三步：创建并执行日志迁移

#### 3.1 迁移脚本
创建迁移脚本 `src/main/scripts/migrate-logs.ts`，将以下目录中的日志文件迁移到统一目录：

| 源路径 | 说明 |
|-------|------|
| `C:\Users\a1299\AppData\Roaming\creative-cafe\logs\` | storageManager 产生的日志 |
| `C:\Users\a1299\AppData\Roaming\creative-cafe\log\` | 可能存在的旧日志目录 |

#### 3.2 迁移规则
- 将源目录中的所有 `*.log` 文件复制到统一日志目录
- 如果存在同名文件，使用时间戳重命名避免覆盖
- 迁移完成后记录迁移日志

### 第四步：验证
- 确认统一日志目录存在且可写入
- 确认各模块日志均写入统一目录
- 确认历史日志文件迁移成功

## 实施步骤详情

### 步骤 1: 创建 `src/main/services/logPathService.ts`

```typescript
import * as fs from 'fs';
import * as path from 'path';

// 统一日志根目录
export const LOG_BASE_DIR = path.join('D:', 'AI', 'creative-cafe', 'logs');

export function getLogDir(): string {
  if (!fs.existsSync(LOG_BASE_DIR)) {
    fs.mkdirSync(LOG_BASE_DIR, { recursive: true });
  }
  return LOG_BASE_DIR;
}

export function getLogFilePath(fileName: string): string {
  return path.join(getLogDir(), fileName);
}
```

### 步骤 2-1: 修改 `src/main/services/AiLogger.ts`

### 步骤 2-2: 修改 `src/main/ipc/handlers/aiHandlers.ts`

### 步骤 2-3: 修改 `src/main/services/fileService.ts`
