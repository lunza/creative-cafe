# 辅助模式选项结构化格式渲染计划

## Summary

在辅助模式下，要求 AI 生成的 3 个推荐选项使用结构化格式：圆括号 `()` 包裹动作/状态/表情/环境描写，双引号 `""` 包裹语言/心理活动。选项渲染时两种类型视觉区分，点击复制到输入框时保留原始格式文本。

### 已有实现详情

1. **PromptBuilder.ts** — 提示词已包含格式要求：用 `()` 包裹动作描写，`""` 包裹对话内容，并给出示例 `(微微一笑)"今天天气真好呢，要一起出去走走吗？"`

2. **ChatMessageBubble.tsx** — `renderOptionContent` 函数用正则 `/\(([^)]*)\)|"([^"]*)"/g` 解析文本，将 `()` 渲染为 `<span className="suggested-option-action">`，`""` 渲染为 `<span className="suggested-option-dialogue">`，未匹配部分为普通 `<span>`

3. **复制保留格式** — `handleSelectOption` 传递原始 `option` 字符串（含 `()` 和 `""`）到 `setGeneratedReplyText`，`ChatInputBar` 用 `execCommand('insertText')` 插入。原始格式天然保留，无需额外修改。

4. **三选项特点保留** — 提示词中仍保留"稳妥推进/平衡探索/发散创新"三选项差异化要求（第 314-317 行），CSS 中已有三色编号系统（绿/紫/橙红），格式化不影响特点标签。

## Proposed Changes

### 唯一待修改：ChatMessageBubble.css — 添加动作/对话差异化样式

**文件**: `src/renderer/components/Character/CharacterDialogueChat/ChatMessageBubble.css`
**位置**: 第 118 行 `.suggested-option-text` 之后、第 120 行响应式区块之前

新增两个样式类：

```css
/* 动作描写（() 包裹内容）：斜体、颜色稍淡 */
.suggested-option-action {
  font-style: italic;
  color: rgba(255, 255, 255, 0.55);
}

/* 对话内容（"" 包裹内容）：正常颜色，略带高亮 */
.suggested-option-dialogue {
  color: rgba(255, 255, 255, 0.95);
}
```

设计理由：
- 动作描写用斜体+较暗色调，与对话内容形成视觉层次
- 对话内容用较亮色调，使其成为视觉焦点
- 两者都在 `.suggested-option-text`（13px, line-height 1.5）内联，继承基础排版

## Assumptions & Decisions

1. **格式解析在渲染层做**：选项存储为原始字符串（含 `()` 和 `""`），渲染时解析为样式化元素。存储/复制天然保留格式。
2. **容错处理**：如果 AI 未遵循格式（无括号/引号），`renderOptionContent` 退化为纯文本显示，不影响功能。
3. **三选项特点不受影响**：格式化仅作用于 `.suggested-option-text` 内部，特点标签（稳妥推进/平衡探索/发散创新）和三色编号保持不变。

## Verification Steps

1. 开启辅助模式，发送消息，确认 AI 返回的选项内容包含 `()` 和 `""` 格式
2. 确认选项渲染时动作描写 `()` 为斜体灰色，对话内容 `""` 为正常亮色
3. 点击选项，确认输入框中填入的文本保留 `()` 和 `""` 原始格式
4. 确认三个选项的特点标签（稳妥推进/平衡探索/发散创新）和三色编号仍正常显示
5. AI 未按格式输出时，选项仍能正常纯文本显示
