# 写作模式提示词拼接与日志系统修复计划

## 问题分析

通过代码审查发现以下三个核心问题：

### 问题1：提示词拼接缺少素材资源
当前 `ContentGenerator.ts` 中的 `buildPrompt` 方法调用 `promptBuilder.buildContentPrompt` 时，虽然传入了 `resourceContext`，但在 `writingHandlers.ts` 的 `writing:generateChapter` handler 中，**章节生成请求并未加载和传递角色卡、世界书、用户人设、知识库、写作风格等素材资源**。具体链路：
- `writingHandlers.ts:L352` 的 `writing:generateChapter` handler 只加载了 writingStyleIds，**没有加载 worldBooks、characterCards、userPersonas、knowledgeItems**
- 这些素材在大纲生成阶段（`writingHandlers.ts:L189-L195`）有加载，但在章节生成阶段缺失
- 导致 AI 生成章节时缺乏世界观和角色设定参考

### 问题2：addLog 仅发送到 renderer 和 console，未写入文件
当前 `chatLogService.ts:L17` 的 `addLog` 函数仅调用 `sendLogToRenderer`，而 `sendLogToRenderer`（`index.ts:L22`）只做两件事：
1. 通过 IPC 发送到 renderer 进程
2. `console.log` 打印到控制台

**完全没有写入 ai-handler.log 文件**，导致：
- AI 处理的每个阶段的入参/出参没有持久化记录
- 日志在控制台滚动后无法追溯
- 系统日志中提到"成功生成的信息被删除"，实际上是因为日志根本没写入文件，只是 console.log 输出后随终端清空消失

### 问题3：日志轮转/清理机制干扰
当前没有日志轮转配置，但由于日志未写入文件，所以不存在"被删除"的问题。需要建立正确的日志文件写入机制，并防止文件过大影响性能。

## 实施步骤

### 步骤1：创建 ai-handler.log 文件日志写入模块

**目标**：在 `chatLogService.ts` 中新增文件日志写入功能，确保所有 `addLog` 调用同时写入到 `ai-handler.log` 文件。

**具体操作**：
1. 在 `chatLogService.ts` 中新增 `writeToFileLog` 函数：
   - 日志文件路径：`getUserDataPath()/logs/ai-handler.log`
   - 日志格式：`[YYYY-MM-DD HH:mm:ss.SSS] [LEVEL] [WRITING] message`
   - 使用 `fs.appendFileSync` 追加写入，确保性能
   - 添加 try-catch 异常处理，写入失败时 console.error 但不阻塞主流程
2. 修改 `addLog` 函数，在原有 `sendLogToRenderer` 基础上追加调用 `writeToFileLog`
3. 实现日志文件自动轮转：当文件超过 10MB 时，备份为 `ai-handler.log.1`，并新建文件（最多保留 3 个备份）
4. 添加请求 ID 机制：每次 AI 请求生成唯一 ID，附加到该请求相关的所有日志行

### 步骤2：增强章节生成日志记录

**目标**：确保 AI 处理的每个阶段都有详细日志输出，包含完整的入参和出参。

**具体操作**：
1. 在 `ContentGenerator.ts` 的 `generateStream` 方法中，增强以下阶段的日志：
   - **接收请求阶段**：记录章节 ID、项目 ID、模型配置、前序章节数量、素材资源数量
   - **参数验证阶段**：记录 baseUrl、apiKey 是否存在（脱敏）、model name
   - **提示词生成阶段**：记录完整提示词（messages 数组的完整内容）
   - **AI 调用阶段**：记录请求开始时间、请求体（脱敏 API key）
   - **结果处理阶段**：记录完整响应内容、生成耗时、token 估算
   - **返回响应阶段**：记录最终返回给前端的响应摘要
2. 统一日志格式：所有日志行包含 `[writing]` 前缀标识
3. 确保 `addLog` 在 `ContentGenerator.ts` 中记录完整内容而非仅长度

### 步骤3：修复提示词拼接模块，补全素材资源

**目标**：在章节生成时加载并传递完整的素材资源到提示词中。

**具体操作**：
1. 修改 `writingHandlers.ts` 的 `writing:generateChapter` handler（L352行附近）：
   - 从请求中提取 `projectId`
   - 加载项目数据以获取配置中关联的素材 ID
   - 如果请求中携带了 `resources` 参数（worldBookIds、characterCardIds、userPersonaIds、knowledgeItemIds、writingStyleIds），则全部加载
   - 使用 `writingResourceManager.buildResourceContextSummary` 构建完整的素材上下文
   - 将素材上下文注入到请求的 `worldBookContext` 和 `characterContext` 字段
   - 将写作风格上下文注入到 `generationParams.writingStyleContext`
2. 修改 `ContentGenerator.ts` 的 `buildResourceContext` 方法：
   - 确保除了 `worldBookContext` 和 `characterContext` 外，还支持 `userPersonaContext` 和 `knowledgeContext` 和 `writingStyleContext`
   - 在提示词中按优先级排列：角色信息 → 世界观设定 → 用户人设 → 知识库 → 写作风格
3. 确保素材完整性校验：
   - 如果请求指定了素材 ID 但加载失败，记录 warning 日志
   - 如果关键素材（如当前章节涉及的角色）缺失，记录 warning 但不阻塞生成
4. 在 `PromptBuilder.ts` 的 `buildContentPrompt` 中确保所有素材都正确纳入提示词

### 步骤4：验证与测试

**具体操作**：
1. 运行 `npm run build` 确认编译通过
2. 检查 `ai-handler.log` 文件是否正确生成在 `userData/logs/` 目录
3. 触发一次章节生成，检查日志文件内容是否包含完整入参出参
4. 检查提示词是否包含完整的素材上下文（角色卡、世界书等）
