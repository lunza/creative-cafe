# 写作模式章节生成按钮无请求问题修复计划

## 问题描述

在写作模式下，用户点击"生成"按钮后，界面持续显示"正在生成中..."状态，但前端未向AI服务发起任何生成请求。

## 根因分析

经过对代码链路（[useChapterGeneration.ts](file:///d:/AI/creative-cafe/src/renderer/components/Creative/WritingMode/hooks/useChapterGeneration.ts) → [writingHandlers.ts](file:///d:/AI/creative-cafe/src/renderer/components/Creative/WritingMode/hooks/useChapterGeneration.ts#L310) → [ContentGenerator.ts](file:///d:/AI/creative-cafe/src/main/services/writing/ContentGenerator.ts)）的逐层追踪，发现以下问题：

### 根因1：配置字段名错误 + activeEngine 查找逻辑不匹配

在 `useChapterGeneration` hook 顶层（第53-54行）：
```typescript
const aiEngines = setting?.ai_engines || [];
const activeEngine = aiEngines.find((e) => e.is_active) || aiEngines[0];
```

存在两个致命问题：

1. **字段名不匹配**：[AppSetting](file:///d:/AI/creative-cafe/src/renderer/types/setting.ts) 类型定义明确使用 `aiEngines`（驼峰命名，第167行），而 hook 中读取的是 `ai_engines`（下划线命名）。因此 `setting?.ai_engines` 始终为 `undefined`，`aiEngines` 为空数组，`activeEngine` 为 `undefined`。

2. **activeEngine 查找逻辑错误**：正确的查找方式应基于 `setting.activeEngineId` 匹配 `aiEngines[].id`（参考 [settingStore.ts](file:///d:/AI/creative-cafe/src/renderer/stores/settingStore.ts) 第140-144行的 testConnection 逻辑）。而 hook 中使用了不存在的 `is_active` 字段（AIEngineSetting 类型中无此字段），导致即使字段名正确也无法找到引擎。

### 根因2：闭包捕获过时值

`activeEngine` 在 hook 顶层计算后，被 `handleGenerateChapter` 的 `useCallback` 闭包捕获。由于 `useCallback` 依赖数组（第322行）为 `[outline, isGenerating, chapterContents, projectId]`，缺少 `setting` 和 `activeEngine`，即使组件因 setting 更新而重新渲染，回调仍使用旧的 `undefined` 值。

### 根因2：配置错误在 try-catch 外部抛出

在 `handleGenerateChapter` 中（第256-263行），`modelConfig` 的构建在 try-catch **外部**执行：

```typescript
const modelConfig = {
  model: activeEngine?.model_name ?? (() => { throw new Error('未配置 AI 模型名称') })(),
  temperature: Number(activeEngine?.temperature) ?? (() => { throw new Error('未配置 temperature 参数') })(),
  maxTokens: Number(activeEngine?.max_tokens) ?? (() => { throw new Error('未配置 max_tokens 参数') })(),
};

try {
  await window.electronAPI?.writing?.generateChapter(request);
} catch (error: any) { ... }
```

当 `activeEngine` 为 `undefined` 时：
- `activeEngine?.model_name` 返回 `undefined`
- `??` 操作符触发右侧的 IIFE，抛出 `Error('未配置 AI 模型名称')`
- **该错误在 try-catch 外部抛出**，导致：
  - `setIsGenerating(true)` 已执行，UI显示"正在生成中"
  - 错误未被捕获，`setIsGenerating(false)` 和 `setGenerationState(ERROR)` 不会执行
  - 状态永久停留在 GENERATING

### 根因3：IPC调用可能静默失败

第310行的调用使用了可选链：
```typescript
await window.electronAPI?.writing?.generateChapter(request);
```

如果 `window.electronAPI?.writing?.generateChapter` 为 `undefined`（可选链短路），`await undefined` 会立即返回，但 `isGenerating` 已设置为 `true`，导致UI永久显示加载状态。

## 修复方案

### 修复1：修正配置字段名 + 从Store实时读取engine

**文件**：`src/renderer/components/Creative/WritingMode/hooks/useChapterGeneration.ts`

**修改内容**：

1. 移除顶层的 `activeEngine` 计算（原第53-54行）
2. 在 `handleGenerateChapter` 的 `useCallback` 内部，从 store 实时读取当前配置
3. 将 `setting` 和 `activeEngine` 加入 `useCallback` 依赖数组
4. 同时兼容两种字段名（`aiEngines` 和 `ai_engines`）

```typescript
// 删除顶层的这两行：
// const aiEngines = setting?.ai_engines || [];
// const activeEngine = aiEngines.find((e) => e.is_active) || aiEngines[0];

// 在 handleGenerateChapter 的 useCallback 内部，abortController 创建之前添加：
const currentSetting = useSettingStore.getState().setting;
const engines = currentSetting?.aiEngines || currentSetting?.ai_engines || [];
const engine = engines.find((e: any) => e.is_active) || engines[0];

if (!engine) {
  message.error('未配置 AI 引擎，请先在设置中配置 AI 服务');
  setIsGenerating(false);
  setGenerationState(GenerationState.IDLE);
  setChapterStatuses(prev => ({ ...prev, [chapterIndex]: ChapterStatus.PENDING }));
  return;
}

const modelConfig = {
  model: engine.model_name,
  temperature: Number(engine.temperature),
  maxTokens: Number(engine.max_tokens),
};
```

### 修复2：将配置验证和请求构建移入 try-catch 内部

**文件**：`src/renderer/components/Creative/WritingMode/hooks/useChapterGeneration.ts`

将 `modelConfig` 构建、`request` 对象构建等所有可能抛错的逻辑全部移入 try-catch 块内：

```typescript
const handleGenerateChapter = useCallback(async (chapterIndex: number) => {
  if (!outline || isGenerating) return;

  const chapter = outline.chapters.find(ch => ch.index === chapterIndex);
  if (!chapter) return;

  // 立即设置状态
  stopRef.current = false;
  pauseRef.current = false;
  isPausedRef.current = false;
  setIsGenerating(true);
  setGenerationState(GenerationState.GENERATING);
  setChapterStatuses(prev => ({ ...prev, [chapterIndex]: ChapterStatus.GENERATING }));
  setStreamingContent('');
  setCurrentChapterWords(0);
  setSelectedChapterIndex(chapterIndex);

  try {
    abortControllerRef.current = new AbortController();

    // 实时读取配置
    const currentSetting = useSettingStore.getState().setting;
    const engines = currentSetting?.aiEngines || currentSetting?.ai_engines || [];
    const engine = engines.find((e: any) => e.is_active) || engines[0];

    if (!engine) {
      throw new Error('未配置 AI 引擎，请先在设置中配置 AI 服务');
    }

    if (!engine.model_name) {
      throw new Error('未配置 AI 模型名称');
    }
    if (engine.temperature === undefined || engine.temperature === null) {
      throw new Error('未配置 temperature 参数');
    }
    if (engine.max_tokens === undefined || engine.max_tokens === null) {
      throw new Error('未配置 max_tokens 参数');
    }

    const modelConfig = {
      model: engine.model_name,
      temperature: Number(engine.temperature),
      maxTokens: Number(engine.max_tokens),
    };

    // 获取当前项目（实时读取，避免ref过期）
    const currentProject = useWritingProjectStore.getState().getCurrentProject();
    if (!currentProject) {
      throw new Error('未找到当前项目');
    }

    // ... 构建 request 对象 ...

    // 检查 IPC 方法是否存在
    if (!window.electronAPI?.writing?.generateChapter) {
      throw new Error('IPC 通信模块未就绪，请重启应用');
    }

    await window.electronAPI.writing.generateChapter(request);
  } catch (error: any) {
    if (error.name === 'AbortError') {
      setGenerationState(GenerationState.STOPPED);
      message.info('已停止生成');
    } else {
      message.error(error.message || '生成失败');
    }
    setChapterStatuses(prev => ({ ...prev, [chapterIndex]: ChapterStatus.FAILED }));
    setIsGenerating(false);
    setGenerationState(GenerationState.ERROR);
  }
}, [outline, isGenerating, chapterContents, projectId, setting]); // 添加 setting 依赖
```

将 `handleGenerateChapter` 的 `useCallback` 依赖数组补充完整：

}, [outline, isGenerating, chapterContents, projectId, setting]);

### 修复4：`currentProjectRef` 实时更新机制

**文件**：`src/renderer/components/Creative/WritingMode/hooks/useChapterGeneration.ts`

原代码在 `handleGenerateChapter` 内部使用 `currentProjectRef.current`（第255行），该 ref 通过 useEffect 更新，但存在时序问题。

**修改**：在 `handleGenerateChapter` 内部直接使用 `useWritingProjectStore.getState().getCurrentProject()` 实时获取当前项目，避免 ref 过期。

## 修复后预期效果
