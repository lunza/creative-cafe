# 向量管理系统重构计划

## 📋 背景与目标

当前向量管理系统存在以下问题：
1. 所有向量数据存储在单文件 `vecstore.json`，长期会导致性能下降
2. 向量文件与源文件之间缺乏关联关系记录
3. 无法按来源类型（知识库/世界书/文档）分别管理和优化存储

本次重构目标：
- 实现按来源分文件存储的向量管理系统
- 创建中间表记录向量文件与源文件的关联关系
- 规范化向量文件命名
- 支持多维度的向量管理、查询和统计

## 🔍 数据流图

### 存储流程

```
用户操作（知识库向量化/世界书向量化/文档上传）
    ↓
对应服务（KnowledgeBaseService/worldBookService/DocumentProcessorService）
    ↓
生成向量 + metadata（含 source 字段）
    ↓
VectorStoreService.add() 或 addBatchNoPersist()
    ↓
根据 metadata.source 路由到对应 VecstoreVectorStore 实例
    ↓
VecstoreVectorStore 存储到 vectors/{source}/vecstore.json
    ↓
VectorRegistryService 注册到 vector_registry.json
    ↓
VectorStoreService.persist() 持久化所有 store
```

### 搜索流程

```
用户搜索请求
    ↓
VectorStoreService.search()
    ↓
┌─────────────────────────────────────┐
│  根据 options 决定搜索策略          │
│  - sourceType 指定: 搜索单个 store  │
│  - aggregate=true: 搜索所有 store   │
│  - 默认: 搜索默认 store             │
└─────────────────────────────────────┘
    ↓
合并结果（如聚合搜索）
    ↓
按相似度排序，返回 TopK
    ↓
返回搜索结果
```

### 删除流程

```
删除请求（ID 或前缀）
    ↓
VectorStoreService.delete() 或 deleteByPrefix()
    ↓
─────────────────────────────────────┐
│  遍历所有 store 查找并删除          │
│  或根据 sourceType 定位单个 store   │
└─────────────────────────────────────┘
    ↓
VectorRegistryService 更新注册表
    ↓
VectorStoreService.persist() 持久化
```

## ⚠️ 注意事项

### 1. 数据兼容性

- 当前向量化数据已完全清空，无需考虑历史数据迁移
- 旧文件 `vecstore.json` 可以保留作为备份或直接删除

### 2. 向后兼容性

- `search()` 方法默认行为保持不变（搜索默认 store）
- 新增的 `sourceType` 和 `aggregate` 参数为可选
- 现有调用方无需修改即可正常工作

### 3. 性能考虑

- 多 WASM 实例会增加内存占用（每个约 10-20MB）
- 聚合搜索会增加查询时间（多次 WASM 搜索）
- 注册表文件应定期清理无效记录

### 4. 错误处理

- WASM 初始化超时处理（已在现有代码中实现）
- 目录创建失败的错误处理
- 注册表持久化失败的降级策略
