# 修复：角色卡对话异步整理模式表格自动创建功能失效

## 问题描述

在角色卡对话过程中启用异步整理模式（async mode）时，AI 生成的 tableEdit 命令执行失败。日志显示 `TableTemplateService` 多次报告"表格文件不存在"，但原有逻辑设计为当检测到表格不存在时，应自动使用默认模板创建新表格。

## 根因分析

### 1. 执行流程差异

**同步整理模式（processChatProgressive）：**
- `chatLogService.ts:L2535-L2560` 中，在执行任何 tableEdit 命令之前，会显式检查表格文件是否存在：
  ```typescript
  const safeChatId = chatId.replace(...)
  tableFilePath = path.join(this.chatlogDir, `${safeChatId}.json`);
  if (!fs.existsSync(tableFilePath)) {
    tableTemplateService.createTableFile(chatId, effectiveTemplateId, safeChatId);
  }
  ```
- 因此表格文件在执行命令前一定已创建。

**异步整理模式（CharacterDialogueChat.hooks.ts:L860）：**
- 直接调用 `window.electronAPI.memory.executeTableEditCommands(chatId, parseResult.commands)`
- 该 IPC handler 在 `memoryHandlers.ts:L412` 直接调用 `chatLogService.executeTableEditCommands(chatId, commands)`
- `executeTableEditCommands` (L1166) 内部直接调用 `tableTemplateService.insertRowToTable(chatId, tableIndex, data)`
- `insertRowToTable` (L572) 调用 `readJsonFile(chatId)` → 返回 `null` → 打印错误 "表格文件不存在" → 返回 `false`
- **整个过程没有任何自动创建表格文件的逻辑。**

### 2. 具体失效链路

```
AI返回包含tableEdit的响应
  → 正则匹配检测到tableEdit标签 (CharacterDialogueChat.hooks.ts:L820)
  → parseTableEdit解析命令 (L851)
  → executeTableEditCommands执行命令 (L860)
  → IPC: memory:executeTableEditCommands (memoryHandlers.ts:L412)
  → chatLogService.executeTableEditCommands (chatLogService.ts:L1166)
  → tableTemplateService.insertRowToTable (chatLogService.ts:L1235)
  → readJsonFile(chatId) 返回 null (tableTemplateService.ts:L472)
  → 打印 "表格文件不存在" 并返回 false (tableTemplateService.ts:L577)
```

### 3. 为什么没有触发自动初始化

- `autoInitializeChatSession` 方法在 `getTableData` 中被调用 (L3224)，但只在文件不存在时通过 `getTableData` 的 fallback 路径触发
- 在异步整理模式中，`executeTableEditCommands` 是一个独立的调用，没有调用 `getTableData`
- 因此 `autoInitializeChatSession` 永远不会被触发

### 4. safeChatId 一致性

所有位置都使用了相同的 safeChatId 计算逻辑（12种特殊字符替换），因此路径解析不是问题。问题纯粹在于**缺少自动创建表格文件的前置检查**。

## 修复方案

### 方案一：在 `executeTableEditCommands` 中添加自动初始化检查（推荐）

**修改位置：** `chatLogService.ts` 的 `executeTableEditCommands` 方法（L1166）

**修改内容：** 在执行命令前，检查表格文件是否存在，如果不存在则自动创建。

```typescript
private executeTableEditCommands(chatId: string, commands: any[]): { success: boolean; executed: number; errors: string[] } {
    const result = { success: true, executed: 0, errors: [] as string[] };

    if (!commands || commands.length === 0) {
      addLog('没有需要执行的tableEdit的命令', 'debug');
      return result;
    }

    // 【新增】确保表格文件存在（修复异步整理模式下表格文件未创建的问题）
    const safeChatId = chatId
      .replace(/\//g, '_')
      .replace(/\\/g, '_')
      .replace(/\s+/g, '_')
      .replace(/@/g, '_')
      .replace(/-/g, '_')
      .replace(/:/g, '_')
      .replace(/\*/g, '_')
      .replace(/\?/g, '_')
      .replace(/"/g, '_')
      .replace(/</g, '_')
      .replace(/>/g, '_')
      .replace(/\|/g, '_');
    const tableFilePath = path.join(this.chatlogDir, `${safeChatId}.json`);
    if (!fs.existsSync(tableFilePath)) {
      addLog(`[executeTableEditCommands] 表格文件不存在，尝试自动初始化`, 'info');
      // 优先使用关联的模板，如果没有则使用默认模板
      let templateId = this.getAssociatedTemplate(chatId);
      if (!templateId) {
        const allTemplates = tableTemplateService.getAllTemplates();
        if (allTemplates && allTemplates.length > 0) {
          templateId = allTemplates[0].id;
          addLog(`[executeTableEditCommands] 无关联模板，使用默认模板: ${templateId}`, 'info');
        } else {
          addLog('[executeTableEditCommands] 没有可用的表格模板，无法自动创建', 'error');
          result.errors.push('表格文件不存在且没有可用的模板');
          return result;
        }
      }
      try {
        tableTemplateService.createTableFile(chatId, templateId, safeChatId);
        addLog(`[executeTableEditCommands] 表格文件已自动创建: ${tableFilePath}`, 'info');
      } catch (createError) {
        addLog(`[executeTableEditCommands] 创建表格文件失败: ${createError}`, 'error');
        result.errors.push(`创建表格文件失败: ${createError}`);
        return result;
      }
    }

    addLog(`开始执行 ${commands.length} 个tableEdit命令`, 'info');
    // ... 后续原有代码不变
```

**优点：**
- 一处修复，所有调用 `executeTableEditCommands` 的地方（包括异步整理、IPC 直接调用）都受益
- 保持与 `processChatProgressive` 相同的 safeChatId 计算逻辑
- 优先使用已关联的模板，如果没有才使用默认模板，符合业务逻辑
- 完善的错误处理和日志记录

**缺点：**
- 无

### 方案二：在 IPC handler 中添加检查（不推荐）

**缺点：** 如果有其他地方直接调用 `chatLogService.executeTableEditCommands`，仍会失败。修复不够彻底。
