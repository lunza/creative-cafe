# 修复角色对话实时整理表格功能异常 - 增量更新实现计划

## 问题分析

当前角色对话中"实时整理表格"功能存在以下问题：

1. **非真正的增量更新**：虽然`processChatProgressive`方法通过`processedCount`实现了消息级别的断点续传（不重复处理已处理的消息），但AI在处理新消息时，可能生成重复的insert命令，导致表格中出现重复数据

2. **表格上下文格式不够清晰**：`buildTableContext`方法生成的表格数据格式使用JSON序列化，AI难以快速理解现有数据结构

3. **缺乏去重保护机制**：在执行tableEdit命令前，没有检查是否会创建重复记录

4. **缺少回滚机制**：如果整理过程中出现异常，已执行的命令无法回滚

## 修复方案

### 2. 增强AI提示词中的增量更新策略（chatLogService.ts - buildAIPromptForProgressive方法）

**目标**：在提示词中明确强调增量更新策略，避免AI生成重复操作

**修改位置**：`src/main/services/memory/chatLogService.ts` 第785-902行

**修改内容**：
- 在提示词开头明确说明"这是增量更新，只处理当前消息中的新信息"
- 添加"去重检查规则"：在生成insert命令前，必须先检查现有数据中是否已存在相同唯一id的记录
- 如果存在相同唯一id，必须使用updateRow而非insertRow
- 添加明确的"增量更新流程图"：
  ```
  1. 从当前消息中识别实体
  2. 检查表格中是否已有该实体（通过唯一id或关键特征匹配）
  3. 如果存在 → 使用updateRow更新该实体信息
  4. 如果不存在 → 使用insertRow创建新记录
  5. 如果实体不再相关 → 使用deleteRow删除（谨慎使用）
  ```

**新增提示词段落**：
```
【增量更新策略 - 重中之重】
这是增量更新操作，你必须遵循以下规则：

1. **检查现有数据**：在生成任何insertRow命令前，必须仔细检查上述"当前数据"部分
2. **唯一id匹配**：如果现有数据中已有相同唯一id的记录，必须使用updateRow而非insertRow
3. **名称匹配**：即使唯一id不同，如果角色名/物品名/地点名高度相似，也应使用updateRow
4. **避免重复**：绝不要为已存在的实体生成新的insertRow命令
5. **只更新变化部分**：使用updateRow时，只更新发生变化的字段，不要重复填写未变化的字段

示例：
- 现有数据：行1: 唯一id=zhudi_001, 角色名=朱迪·霍普斯
- 当前消息："朱迪说她今天升官了"
- 正确操作：updateRow(1, 1, {"4":"警长"})  ← 只更新身份字段
- 错误操作：insertRow(1, {"2":"zhudi_001","3":"朱迪·霍普斯","4":"警长"})  ← 重复插入！
```

### 3. 添加命令执行前的去重检查（chatLogService.ts - executeTableEditCommands方法）

**目标**：在执行insertRow命令前，检查是否会创建重复记录

**修改位置**：`src/main/services/memory/chatLogService.ts` 第910-993行

**修改内容**：
- 在执行insertRow命令前，读取当前表格数据
- 检查新数据的唯一id或关键字段是否已存在
- 如果已存在，将insertRow转换为updateRow，或跳过该命令并记录日志
- 添加详细日志记录去重决策过程

**新增逻辑**：
```typescript
case 'insertRow':
  // 去重检查：读取当前表格数据
  const tableData = tableTemplateService.getTableData(chatId, tableIndex);
  const uniqueId = data['2']; // 字段2是唯一id
  const isDuplicate = tableData.some(row => row['2'] === uniqueId);
  
  if (isDuplicate) {
    addLog(`检测到重复插入(唯一id=${uniqueId})，转换为更新操作`, 'warn');
    // 转换为updateRow
    const rowIndex = tableData.findIndex(row => row['2'] === uniqueId) + 1;
    success = tableTemplateService.updateRowInTable(chatId, tableIndex, rowIndex, data);
  } else {
    success = tableTemplateService.insertRowToTable(chatId, tableIndex, data || {});
  }
  break;
```

### 4. 实现操作回滚机制（chatLogService.ts - processChatProgressive方法）

**目标**：在整理过程出现异常时，能够回滚已执行的操作

**修改位置**：`src/main/services/memory/chatLogService.ts` 第2052-2319行

**修改内容**：
- 在处理开始前，备份当前表格数据
- 如果处理过程中出现严重错误（非单条消息处理失败），恢复备份数据
- 添加"操作日志"记录，便于追踪和调试

**新增逻辑**：
```typescript
// 备份当前表格数据
let tableDataBackup: any = null;
try {
  const backupPath = path.join(this.chatlogDir, `${safeChatId}_backup_${Date.now()}.json`);
  if (fs.existsSync(tableFilePath)) {
    tableDataBackup = fs.readFileSync(tableFilePath, 'utf-8');
  }
} catch (error) {
  addLog(`备份表格数据失败: ${error}`, 'warn');
}

// 处理完成后，如果失败且有备份，则恢复
if (hasCriticalError && tableDataBackup) {
  addLog('整理过程出现严重错误，回滚表格数据', 'error');
  fs.writeFileSync(tableFilePath, tableDataBackup, 'utf-8');
}
```
