# 剧情检查功能内容截断优化方案

## 问题分析

经过代码审查，发现以下截断问题：

### 1. 当前章节内容截断（PlotCheckerService.ts:90）
```typescript
const contentPreview = request.content.length > 3000 ? request.content.substring(0, 3000) + '...' : request.content;
```
**问题**：当前章节内容被限制为最多 3000 字符

### 2. 前文章节内容截断（PlotCheckerService.ts:85）
```typescript
const preview = prev.content.length > 1000 ? prev.content.substring(0, 1000) + '...' : prev.content;
```
**问题**：每个前文章节内容被限制为最多 1000 字符

### 3. 前端传递前文章节时截断（ContentWorkspace.tsx:679）
```typescript
content: chapterContents[ch.index]?.substring(0, 2000) || ''
```
**问题**：前端在调用剧情检查时，前文章节被截断为 2000 字符

### 4. maxTokens 配置过低（PlotCheckerService.ts:492）
```typescript
maxTokens: 4000
```
**问题**：AI 返回的最大 token 数限制为 4000，可能导致长文本检查时响应被截断

## 优化方案

### 步骤 1：移除 PlotCheckerService.ts 中的内容截断

**文件**：`src/main/services/writing/PlotCheckerService.ts`

#### 1.1 移除当前章节内容截断（第 90-92 行）
```typescript
// 修改前
const contentPreview = request.content.length > 3000 ? request.content.substring(0, 3000) + '...' : request.content;
contextParts += `## 当前章节内容\n${contentPreview}`;

// 修改后
contextParts += `## 当前章节内容\n${request.content}`;
```

#### 1.2 移除前文章节内容截断（第 84-87 行）
```typescript
// 修改前
for (const prev of request.previousChapters.slice(-2)) {
  const preview = prev.content.length > 1000 ? prev.content.substring(0, 1000) + '...' : prev.content;
  contextParts += `### ${prev.title}\n${preview}\n\n`;
}

// 修改后
for (const prev of request.previousChapters.slice(-2)) {
  contextParts += `### ${prev.title}\n${prev.content}\n\n`;
}
```

#### 1.3 提高 maxTokens 默认配置（第 492 行）
```typescript
// 修改前
maxTokens: 4000

// 修改后
maxTokens: 40960
```

### 步骤 2：移除 ContentWorkspace.tsx 中的内容截断

**文件**：`src/renderer/components/Creative/WritingMode/ContentWorkspace.tsx`

#### 2.1 移除前端前文章节截断（第 679 行）
```typescript
// 修改前
content: chapterContents[ch.index]?.substring(0, 2000) || ''

// 修改后
content: chapterContents[ch.index] || ''
```

### 步骤 3：添加内容长度日志记录

在 `PlotCheckerService.ts` 的 `checkChapter` 方法中，添加完整内容长度日志，便于调试：

```typescript
addLog(`【剧情检查】当前章节内容完整长度: ${request.content.length} 字符`, 'debug');
if (request.previousChapters) {
  request.previousChapters.forEach((prev, idx) => {
    addLog(`【剧情检查】前文章节 ${prev.title} 内容长度: ${prev.content.length} 字符`, 'debug');
  });
}
const totalPromptLength = systemPrompt.length + userPrompt.length;
addLog(`【剧情检查】完整提示词总长度: ${totalPromptLength} 字符`, 'debug');
```

### 步骤 4：验证测试

1. **长文本测试**：准备一个超过 10000 字符的章节内容，验证是否完整传入
2. **前文章节测试**：准备 2 个以上的前文章节（每篇超过 5000 字符），验证是否完整传入
3. **特殊字符测试**：包含特殊格式、Markdown、Emoji 等内容，验证是否正确处理
4. **边界测试**：测试超长内容（如 50000+ 字符）时系统的表现

## 预期效果

- 当前章节内容完整传入 AI，无任何截断
- 前文章节内容完整传入 AI，支持更多上下文
- 提示词入参出参完整打印，便于调试
- AI 响应 token 限制提高，支持更详细的检查报告

## 风险评估

- **风险**：超长文本可能导致 API 请求超时或 token 超限
- **缓解**：
  - 已有 120 秒超时配置
  - 建议在 UI 层添加内容长度提示
  - 可考虑后续实现智能分片检查机制
