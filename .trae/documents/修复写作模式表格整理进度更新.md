# 修复写作模式表格整理进度更新和内容实时显示计划

## 问题分析

### 根因
1. **后端 `organizeTable` 有 `onProgress` 回调但未使用**：`WritingStorageService.organizeTable()` 支持 `onProgress(current, total, message, percent)` 回调，但 IPC handler 没有传递它
2. **前端不接收增量进度**：`handleStartOrganize` 仅等待最终结果，不轮询进度
3. **分片内无进度更新**：`processChapterWithAI` 处理分片时没有报告子进度
4. **内容未实时更新到UI**：前端只在整理完成后调用一次 `loadTableData()`，分片整理后的数据没有实时刷新到表格

### 附加问题
- 分片整理过程中，每批处理后的表格数据已保存到文件，但前端没有刷新显示
- 进度百分比仅基于章节数量，未考虑分片（chunk）维度

## 解决方案

### 步骤 1: 修改 IPC handler 传递 progress 回调

**文件**: `g:\AI\creative-cafe\src\main\ipc\handlers\writingHandlers.ts`
**位置**: 约第 1189-1203 行

**修改内容**:
- 使用 `event.sender.send('writing:table:organizeProgress', projectId, { current, total, message, percent })` 在 `onProgress` 回调中发送进度事件到渲染进程
- 在 `organizeTable` 方法中传递 `onProgress` 回调

### 步骤 2: 在前端注册进度事件监听器

**文件**: `g:\AI\creative-cafe\src\renderer\components\Creative\WritingMode\WritingTablePreviewModal.tsx`
**位置**: `handleStartOrganize` 方法

**修改内容**:
- 在调用 `organizeTable` 前注册 `ipcRenderer.on('writing:table:organizeProgress', ...)` 监听器
- 在监听器中更新 `organizeProgress` 和 `organizeStatus` 状态
- 整理完成后移除监听器
- 在每个分片处理完成后调用 `loadTableData()` 实时刷新表格内容

### 步骤 3: 增强分片级进度报告

**文件**: `g:\AI\creative-cafe\src\main\services\WritingStorageService.ts`
**位置**: `processChapterWithAI` 方法

**修改内容**:
- 将章节级的 `onProgress` 回调传入 `processChapterWithAI`
- 在每个分片处理完成后调用 `onProgress` 报告子进度
- 分片进度计算：`(已处理分片数 / 总分片数) * 100`

### 步骤 4: 确保前端实时刷新表格内容

**文件**: `g:\AI\creative-cafe\src\renderer\components\Creative\WritingMode\WritingTablePreviewModal.tsx`

**修改内容**:
- 当收到分片完成事件时，调用 `loadTableData()` 刷新表格显示
- 确保表格数据实时更新到UI

### 步骤 5: 增强错误处理

**修改内容**:
- 在 `processChapterWithAI` 中捕获每个分片处理异常
- 在 `handleStartOrganize` 中添加进度事件监听错误处理
- 在IPC handler 中添加 `event.sender` 可用性检查

### 步骤 6: 构建验证

运行 `npm run build` 确保编译成功
