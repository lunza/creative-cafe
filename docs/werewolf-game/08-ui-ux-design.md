## 2. 设计原则

| 原则 | 说明 | 落地约束 |
| :--- | :--- | :--- |
| **信息密度可控** | 同屏信息按阶段分级：播报阶段低密度、推理阶段高密度 | 按钮清单 ≤ 8 个/屏；证言表行高压缩至 32px |
| **暗码绝对不可见** | 玩家任何视图都不渲染 `<!-- 好 -->` 等暗码明文 | 统一走 `react-markdown` + `rehype-raw`；严禁控制台打印 factionCode |
| **阶段切换动效** | 阶段转移触发淡入淡出，终止态专属结算动画 | 复用既有 [`PageTransition`](../../src/renderer/components/Layout/PageTransition.tsx) |
| **响应式布局** | 适配 1280×720 起；右侧模板面板区按阶段动态切换组件 | 左叙事 60% / 右面板 40%，断点 md=992 |
| **无障碍优先** | 键盘可达、屏幕阅读器友好、对比度 ≥ 4.5:1、字号可调 | 所有交互元素带 `aria-label`；颜色不作为唯一信息载体 |
| **真相驱动** | 现场调查/证言收集的所有信息由真相剧本生成，UI 仅展示 | UI 组件不猜测阵营、不提示推理方向 |

### 3.4 Markdown 渲染样式（对齐规则文档第 232-234 行）
规则文档第 233 行要求「表格、Markdown 与特殊符号混合形式」。渲染层复用既有 [`react-markdown`](https://www.npmjs.com/package/react-markdown) + `remark-gfm` + `rehype-raw`（对齐 [01-system-architecture.md](./01-system-architecture.md) §5 复用清单），样式约定：

| Markdown 元素 | 渲染样式 | 备注 |
| :--- | :--- | :--- |
| `<span style="color:#HEX">姓名<!-- 暗 --></span>` | 姓名以角色色渲染；HTML 注释由 rehype-raw 解析后隐藏 | 暗码不可见（§1.2） |
| `表格` | antd `Table` 紧凑模式，行高 32px，斑马纹关闭 | 用于三张信息表 |
| `**粗体**` | 关键证据名、案件地点加粗 | |
| Emoji（🧊💢😨等） | 原样渲染，对齐规则文档第 227-229 行证言情绪 | 不替换为文本 |
| `#快速指令` | 灰阶等宽文本，前置 `#` 高亮为证据色 | 规则文档第 236 行 |
| 系统播报引号 `「」` | 居中灰阶斜体 | 规则文档第 233 行「公正严明」 |

## 6. 交互动效说明

| 动效 | 触发 | 实现 | 时长 |
| :--- | :--- | :--- | :--- |
| **流式叙事打字机** | AI 流式回调 `onNarrativeChunk` | `NarrativePanel` 既有 typing 指示器 + 逐字追加 | 首 token < 2s |
| **按钮 hover** | 鼠标悬停 | antd `Button` 默认 + 证据色边框过渡 | 150ms |
| **证据拖拽到推理画布** | 拖拽证物/证言到画布 | `react-dnd` `useDrag`/`useDrop`，落点高亮证据色 | 200ms |
| **异议弹窗震动** | 玩家出示矛盾证物 | `Modal` + CSS `@keyframes shake`（translateX ±4px） | 400ms |
| **阶段切换淡入淡出** | `phaseMachine.transition` | 复用 `PageTransition` `mode=fade` | 300ms |
| **可搜索点位脉冲** | 现场调查/证言收集 | 瓦片 `!` 黄色背景 `@keyframes pulse` | 循环 1.4s |
| **警报闪烁** | 命案封锁触发 | 状态栏 `Tag` 红色闪烁 + 瓦片 `*` 渐入 | 600ms |
| **打分结果揭晓** | 提交推理后 | `Statistic` 数字滚动 + 等级 Tag 弹出 | 500ms |
| **投票实时增长** | AI 投票回流 | `Progress` 条平滑增长 | 300ms/票 |
| **终止态结算** | 胜利/失败 | 专属动画（胜利金光/失败暗角） | 1.2s |

### 6.1 动效性能预算
对齐 [01-system-architecture.md](./01-system-architecture.md) §7.1 性能要求：

| 指标 | 预算 | 落地手段 |
| :--- | :--- | :--- |
| 瓦片首屏渲染 | < 200ms | AnsiTileMap 纯字符渲染，禁用重排 |
| 阶段切换淡入淡出 | 300ms | `PageTransition` CSS opacity 过渡，不触发布局 |
| 16 角色头像网格 | < 100ms | `Avatar` 懒加载，虚拟列表 |
| 证言表 16 行渲染 | < 50ms | `Table` 虚拟滚动 `virtual=true` |
| 异议弹窗震动 | 400ms | `transform` 动画，不影响主线程 |
| 打字机追加 | 逐 token | 复用 `NarrativePanel` 既有流式逻辑 |
| 减少动效模式 | 0ms 动画 | 检测 `prefers-reduced-motion`，降级为静态高亮 |

> 所有动效使用 `transform`/`opacity` 触发 GPU 合成层，避免 layout/paint 抖动；单帧超过 16ms 的动画须在「减少动效」模式下降级。

| `TESTIMONY` | `dialogue` | §4.3 证言收集面板 |

| `TRIAL` | `voting-panel` | §4.5 投票与决策面板 |

### 7.3 常驻入口（不受阶段影响）
- **角色图鉴**：右上角 `Avatar.Group` 图标，点击打开 §4.1 Drawer
- **事件日志**：右上角时钟图标，点击打开 §4.9 Drawer
- **快速指令**：叙事输入框支持 `#尸检报告` 等（规则文档第 236 行），输入 `#` 触发自动补全

### 7.4 状态注入
`gameStore` 扩展 `WerewolfGameState`（对齐 [05-game-flow-design.md](./05-game-flow-design.md) §14.1），`gameUIStore` 扩展 `werewolf` 视图状态，`GameMainPage` 仅消费 store，不持有本地状态（与既有受控组件模式一致）。

## 8. 无障碍设计考量

| 维度 | 要求 | 实现 |
| :--- | :--- | :--- |
| **键盘导航** | 所有交互元素 Tab 可达，Enter/Space 激活 | antd 组件默认支持；证物拖拽提供 `Shift+方向键` 备选 |
| **屏幕阅读器** | 角色卡、证据、票数有语义标签 | `role="dialog"`/`aria-label`/`aria-live="polite"`（叙事流式追加） |
| **颜色对比度** | 文字与背景 ≥ 4.5:1（WCAG AA） | 角色色用于装饰，关键信息附文字（如「存活」「证据」） |
| **非唯一颜色信息** | 颜色不作为唯一信息载体 | 阵营用 Tag 文字 + 图标；打分用文字「优良中差」+ 颜色 |
| **字号可调** | 90% / 100% / 110% / 125% 四档 | 设置项持久化到 `gameUIStore`，根节点 `font-size` 缩放 |
| **减少动效** | 尊重 `prefers-reduced-motion` | 震动/脉冲动画在用户设置「减少动效」时降级为静态高亮 |
| **焦点可见** | 焦点环清晰 | antd 默认焦点样式 + 证据色焦点环 |
| **表格可读** | 证言表/证据表支持行/列头语义 | `Table` `aria-label` + `column` 语义化标题 |
| **暗码无障碍** | HTML 注释不被屏幕阅读器朗读 | `rehype-raw` 渲染注释为隐藏节点，不进入 a11y 树 |
