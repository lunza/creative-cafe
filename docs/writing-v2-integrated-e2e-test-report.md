## 六、问题记录

### P1（已修复）表格整理在无 API Key 的本地 LLM 引擎下抛错

- **现象**：首轮 E2E 第 1 章表格整理环节报"未配置 API Key"，表格整理失败。
- **根因**：`AIConfigProvider.buildApiEndpoint()` 内部调用 `getApiKey()` / `getModelName()`（缺失时 throw），而本地 LLM 引擎无 `api_key`。内容生成/剧情检查/单条修正走 `getAIConfig()`（非抛错，apiKey 缺失返回 undefined），所以正常；仅表格整理受影响。
- **修复**：
  1. `buildApiEndpoint` 改为非抛错语义——apiKey 缺失返回空字符串，modelName 缺失返回空字符串
  2. `TableOrganizeService` 3 处（L144/L404/L569）去掉 `if (!apiEndpoint.apiKey) throw`，仅保留 apiUrl + modelName 校验；下游 `callAIAPIWithFetch`/`buildAuthHeaders` 已有 `&& apiKey` 守卫，空 key 安全
- **验证**：重跑两轮，第 1-3 章表格整理全部成功 ✅
- **影响范围**：所有使用无 API Key 本地 LLM 引擎的表格整理场景
- **优先级**：高（已解决）

### P2（预存，未修复）第 4 章分片大纲 JSON 解析失败（flaky）

- **现象**：两轮测试第 4 章均因分片大纲 JSON 解析失败（pos 93/109）未完成，正文 0 字。
- **根因**：本地小模型偶发输出非法 JSON；现有 2 次重试不足；第 4 章前序表格数据达 32 行，prompt 更长更易触发。
- **影响**：4 章全量生成断言未达 4/4；verdict 判 FAIL（但整合目标已达成）。
- **与整合无关**：失败在生成前分片大纲阶段，表格整理/剧情审核整合链路完整。
- **优先级**：中（见改进建议 S1）

### P3（观察）剧情检查评分波动

- 第 2 章评分 65（两轮一致偏低），第 1 章 88 / 第 3 章 72。
- 第 2 章问题数最多（9-12 条），含"失忆设定凭空出现""时间线逻辑混乱"等 high 级问题。
- 属本地小模型生成质量波动，非整合缺陷。

### P4（素材冲突）角色卡内容与测试要求根本不一致

- **现象**：用户反馈"文章的内容跟角色卡的描述根本不一致"。
- **根因**：E2E 选用的角色卡 `Lucky.png` 是一张 NSFW 宝可梦角色扮演卡（种族=路卡利欧，含大量色情描述与 `{{user}}` 变量），与测试要求的"通俗白话文 / 现实逻辑 / 西雅图兽人小镇"根本冲突。角色卡内容**完整注入**了生成 prompt（日志：`contextLength=25535, skippedResources=0`），但 AI 面对"现实逻辑小说"与"NSFW 角色卡"的不可调和冲突，选择按大纲创意（西雅图现实故事）生成，导致文章与角色卡描述不符。
- **影响**：文章内容与角色卡设定不一致（海獭兽人 vs 路卡利欧）。**不影响功能整合验证**——表格整理/剧情审核/单条修正/上下文注入链路均正常，角色卡内容冲突属素材选择问题，非代码缺陷。
- **判定**：用户确认"只关注功能整合验证，当前结果已够，无需重跑"。
- **优先级**：低（素材层面，非代码层面；如需角色卡正确影响文章，应选用与测试要求匹配的非 NSFW 角色卡）

## 七、改进建议

| 编号 | 建议 | 优先级 | 说明 |
|------|------|--------|------|
| S1 | 分片大纲 JSON 解析加固 | 高 | ① 重试次数 2→3；② 解析失败时提取 JSON 块重新解析（容错正则）；③ 降低小模型温度（分片大纲用 temperature=0.2）；④ 第 4 章等长 prompt 场景拆分大纲为更小子任务 |
| S2 | 表格整理与剧情审核的 UI 整合确认 | 中 | 本轮通过主进程 API 验证整合链路成立；建议在 UI 层确认"章节创作页"已暴露表格整理入口与单条修正按钮（与 API 行为一致） |
| S3 | 剧情检查评分稳定性 | 低 | 第 2 章评分偏低，可考虑检查 prompt 增加"先抑后扬"结构约束，或多次检查取均值 |
| S4 | 上下文注入 token 预算 | 低 | 第 4 章注入 32 行/3854 字符，随章节增长可能逼近小模型上下文上限；建议表格注入按章节数自适应截断（仅保留最近 2 章表格全量 + 更早章节摘要） |
| S5 | 本地 LLM 引擎 JSON 输出规范 | 低 | 在系统提示词中强化"严格输出合法 JSON，不要任何额外文本"，减少 flaky 概率 |
